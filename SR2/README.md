# 트롤리 문제 — 수업 도입 훅

마이클 샌델 『정의란 무엇인가』의 트롤리 문제 지문(`외부지문 2 (handout).docx`, 지문 1)을
읽기 **전에** 돌리는 3D 체험형 도입 자료.

학생이 직접 두 번 선택하고, 마지막에 **자기 자신의 모순**을 마주하게 만드는 것이 전부입니다.
답을 주지 않고, 지문의 마지막 질문으로 끝냅니다.

> *"같은 산수인데, 왜 답이 달랐습니까?"*

---

## 1. 바로 쓰는 법

### 인터넷이 되는 교실 — 링크만 열면 됩니다

> ## https://totojunior.github.io/MSH/SR2/

교사도 학생도 이 주소 하나면 됩니다. 설치·로그인 **필요 없음**.
학생 크롬북에 배포할 것은 이 링크뿐입니다.

### 인터넷이 안 되는 교실 — 파일로

이 폴더의 `index.html` 을 받아서 **더블클릭**하세요.
three.js가 파일 안에 들어 있어 **완전 오프라인으로 작동**합니다.
USB에 담아 교실 PC에 꽂아도 그대로 실행됩니다. (1.28 MB 단일 파일)

웹폰트(Saira Condensed / Barlow / Spectral)만 인터넷에서 받는데,
없으면 대체 폰트로 떨어질 뿐 **수업은 그대로 굴러갑니다.**

## 2. 수업 진행

### 방식 ① 학생 각자 크롬북 (권장)

이 자료가 설계된 방식입니다. 마지막 대면 화면이 **"당신이"** 무엇을 했는지 짚기 때문에,
학생이 직접 고르지 않으면 그 문장이 남의 얘기가 됩니다.

1. 파일을 Google Classroom / 드라이브로 배포 → 학생이 각자 열기
2. 학생: **STUDENT** 선택 → 8초 안에 각자 **조용히** 두 번 선택
   *(남 눈치 안 보게 하는 것이 중요합니다. 8초 동안 선생님도 말하지 마세요.)*
3. 끝나면 학생 화면에 **① 한 일 / ② 한 일** 두 줄 + 배경색이 뜸
4. 교사: 프로젝터에서 **PROJECTOR** → 교사 콘솔
   - *"주황색 화면 든 사람"* 또는 *"A인 사람"* 하고 한 칸씩 부르고
   - 해당 칸의 **`+`** 를 탭 (길게 누르면 빠르게 올라감)
   - 30명 기준 **약 20초**
5. **SHOW THE CLASS →** → 반 전체 그래프
6. **THE QUESTION →** → 각자 자기 모순을 마주함
7. 그리고 지문을 편다

### 방식 ② 프로젝터 단독

준비 5분. 선생님이 화면 하나로 진행하고 거수로 집계.
간단하지만 **개인의 모순을 짚는 마지막 화면의 힘이 줄어듭니다.**

### 소요 시간

| 구간 | 시간 |
|---|---|
| 오프닝 + 사례 1 (운전석) | 약 3분 |
| 사례 2 (다리 위) | 약 2분 |
| 집계 + 결과 + 대면 | 약 2분 |
| **합계** | **약 6~7분** |

내레이션은 **클릭 / SPACE / →** 로 넘길 수 있어 실제로는 더 빨라집니다.

### 교사에게 권하는 것

- 딜레마를 **먼저 설명하지 마세요.** 모르는 채로 고르게 하세요.
- 8초 동안 아무 말도 하지 마세요. 그 침묵이 수업입니다.
- 사례 1이 끝나면 **왜 그랬는지 묻지 말고** 바로 사례 2로 가세요.
- 마지막 질문에 **대신 답하지 마세요.** 10초쯤 불편하게 두세요.

## 4. 알아둘 제약

**자동 집계는 기대하지 마세요.**
학생이 익명으로 파일만 여는 한 기기 간 자동 동기화는 불가능합니다.
그래서 **교사 콘솔 수동 집계가 주 경로**로 설계돼 있고, 그것만으로 수업이 완결됩니다.

**탭을 백그라운드로 돌리면 애니메이션이 멈춥니다.**
브라우저가 `requestAnimationFrame`을 정지시키기 때문입니다. 탭을 다시 보면 즉시 따라잡습니다.

**충돌 장면이 있습니다.**
전차가 사람을 치는 장면이 나옵니다. 피·잔혹 묘사는 없고 저폴리 스타일이지만,
소리와 카메라와 정적으로 무게를 만듭니다. 고2 기준으로 만들었고,
`S` 키로 건너뛸 수 있으며 시작 전 경고 문구도 나옵니다.

## 5. 설계상 건드리면 안 되는 것

나중에 손볼 때 **되돌리면 수업이 망가지는** 결정들입니다.

### 두 사례의 조작은 반드시 동일해야 함
사례 2를 "꾹 누르기"나 "드래그"로 만들면, *"밀지 않았다"* 에
**조작을 못 해서 못 민 학생**이 섞입니다. 그런데 마지막 대면 화면의 결론은 그 수치에서 나옵니다.
도덕적 비대칭은 **이야기**(손으로 사람을 민다)가 만들어야지 입력 난이도가 만들면 안 됩니다.
→ 둘 다 **클릭 한 번**.

### 충돌 후에는 소리를 먼저 끊고 화면은 살려둘 것
```
0.00초  충돌
0.35초  소리 끊김 (정적 2.6초)   ← 화면은 그대로
1.70초  느린 암전 (0.55초)
3.90초  판정 카드
```
암전을 앞당기면 정적이 **검은 화면**에 걸려 아무 무게가 없어집니다.
결과를 보는 시간(1.7초)이 이 장면의 전부입니다.

### 반 결과는 두 선택이 **모두 끝난 뒤에** 보여줄 것
사례 1 결과를 먼저 보여주면 사례 2의 답이 오염됩니다.

### 오렌지(`#ff6a1a`)는 사람에게만
화면에서 유일한 따뜻한 색이고, "사람이 저기 있다"는 신호입니다.
다른 것이 더 밝아지면 시선이 분산됩니다. (한때 플레이어의 손이 조끼보다 밝아서 고쳤습니다.)

### A/B/C/D는 보조, 문장이 주인
학생 카드·교사 콘솔·결과 화면 모두 **① 한 일 / ② 한 일**이 헤드라인입니다.
글자는 호명용 태그, 색은 교실 뒤에서 세기 위한 신호입니다.

## 6. 수정하는 법

`index.html` 은 **빌드 산출물**입니다. 모듈 11개를 이어붙이고 three.js를 내장해
한 파일로 만든 것이므로, **직접 고치지 마세요** — 다음 빌드에 덮어써집니다.
고칠 것은 전부 `src/` 안에 있습니다.

### 깃헙에서만 작업해도 됩니다

`src/` 의 파일을 github.com에서 고쳐 커밋하면, **GitHub Actions가 자동으로
`index.html` 을 다시 만들어 커밋**합니다. 몇 분 뒤 라이브 페이지에 반영됩니다.

- 워크플로우: `.github/workflows/sr2-build.yml`
- 수동 실행: 저장소 **Actions** 탭 → *Build SR2* → *Run workflow*
- 빌드가 실패하면 커밋하지 않습니다 (깨진 페이지가 수업용 페이지를 덮어쓰지 않도록)

### 로컬에서 작업할 때

```bash
node src/assemble.js          # src/*  ->  index.html
node src/serve.js             # http://127.0.0.1:8766/index.html 로 확인
```

### 파일

`src/` 안:

| 파일 | 내용 |
|---|---|
| `mod-copy.js` | **모든 영어 문구와 타이밍** (`SCRIPT`). 문구·속도 조정은 대부분 여기 |
| `mod-ko.js` | 한국어 사전 (`KO`). 영어 원문 → 한국어. 없으면 영어만 나옴 |
| `mod-audio.js` | 절차적 사운드 엔진 (`SFX`). 오디오 파일 0개, 전부 Web Audio 합성 |
| `mod-worldA.js` | 사례 1 — 운전석 3D 씬 |
| `mod-worldB.js` | 사례 2 — 다리 위 3D 씬 |
| `mod-fx.js` | 포스트프로세싱 + 카메라 리그 (`FX`, `CamRig`) |
| `mod-ui.js` / `.css` / `.html` | 화면·HUD·버튼·집계 (`UI`) |
| `00-director.js` | 저장소 · 집계 (`Store`, `Poll`) |
| `01-shell.js` | 자가발행 셸 (아티팩트 호스팅용. 로컬 파일에선 미사용) |
| `02-director.js` | **비트 머신** — 장면 순서와 타이밍의 주인 |
| `base.css` | 디자인 토큰 (팔레트·폰트) |
| `serve.js` | 테스트용 로컬 서버 (utf-8 헤더) |

`vendor/three.r134.min.js` 는 빌드가 페이지에 내장하는 three.js입니다. 이게 없으면 빌드가 조용히 실패합니다.

(`mod-humans.js` 는 두 월드가 각자 인체를 구현하면서 죽은 코드가 되어 빌드에서 빠졌고, 저장소에도 없습니다.)

### three.js 제약 (중요)

**r134 고정.** cdnjs에 남은 마지막 UMD 빌드이고, r135+ 는 404입니다.
`src/THREE-CONSTRAINTS.md` 에 상세히 적어뒀지만 요점만:

- ❌ `CapsuleGeometry` (r140+) → 실린더 + 반구로 조립
- ❌ `EffectComposer` / `BufferGeometryUtils` / `examples/jsm` 전부 → 포스트는 렌더타깃 + 자작 셰이더
- ❌ `outputColorSpace` / `SRGBColorSpace` (r152+) → `outputEncoding` / `sRGBEncoding`
- ⚠️ 색 관리는 **FX가 소유**합니다. 렌더러에 톤매핑·감마를 또 걸면 이중 적용돼 화면이 창백해집니다.

### 검증하는 법

```bash
node src/serve.js             # http://127.0.0.1:8766/index.html
```
⚠️ 브라우저 자동화는 `file://` 을 못 엽니다. 반드시 로컬 서버로.

자동화 탭에서는 `requestAnimationFrame` 이 **아예 안 돌기** 때문에, 수동 구동기가 있습니다:

```js
Director.step(120, 1/60)   // 3D·물리·비트 120프레임 진행
UI.pumpTick(120, 1/60)     // 카운트다운·자막·게이지·막대 120프레임 진행
Director.go('b_choice')    // 특정 비트로 점프
```

이거 없이 측정하면 **"렌더가 안 돈다 / 게이지가 안 찬다"는 유령 결함**을 보게 됩니다.
(실제로 이 프로젝트에서 네 번 겪었습니다.)
