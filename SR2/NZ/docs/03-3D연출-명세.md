# 03 · 3D 연출 명세 — 작은 철학 법정과 노직

대상: `SR2/NZ/src/mod-court.js` 를 쓸 구현자.
이 문서만 보고 `window.NZ.Court` 를 만들 수 있어야 하고, `ui.js` 구현자는 §10만 읽으면 호출할 수 있어야 한다.

## 1. 제약 재확인 (협상 대상 아님)

### 1.1 three.js r134 — 쓰면 안 되는 것

`src/THREE-CONSTRAINTS.md` 의 "NOT available" 목록을 그대로 따른다. 이 문서에 등장하는 API는 전부 r134 코어에 있는 것만이다.

| 금지 | 이 문서의 대체 |
|---|---|
| `CapsuleGeometry` (r140+) | `CylinderGeometry` + `SphereGeometry` 반구 캡. §4 몸통·팔이 전부 이 방식 |
| `BufferGeometryUtils` | 손으로 만든 `mergeParts()` — `SR2/src/mod-worldB.js:193` 을 그대로 가져온다 |
| `EffectComposer` / `UnrealBloomPass` / `FXAA` / `ShaderPass` | **후처리 없음.** 톤매핑·감마는 렌더러 속성으로만 |
| `OrbitControls` / `GLTFLoader` / `examples/jsm` 전부 | 카메라는 고정. 모델은 전부 절차적 도형 |
| `outputColorSpace` / `SRGBColorSpace` / `ColorManagement` (r152+) | `renderer.outputEncoding = THREE.sRGBEncoding`, `texture.encoding = THREE.sRGBEncoding` |
| `WebGLRenderTarget({samples})` | 렌더 타깃 자체를 안 쓴다 |

> 헷갈리기 쉬운 것: `CircleGeometry` 는 r134에 있지만 이 문서는 쓰지 않는다. 안경 렌즈는 `CylinderGeometry(r, r, 0.004, 20)` 원판으로 만든다 — THREE-CONSTRAINTS.md 가 "확인됨"으로 명시한 목록 안에서만 움직이기 위해서다. 굳이 목록 밖으로 나가서 얻을 게 없다.

### 1.2 빌드 제약

`SR2/src/assemble.js` 와 같은 검사기가 `SR2/NZ/src/assemble.js` 에도 붙는다. 다음은 **빌드를 실패시킨다**:

- `import` / `export` 로 시작하는 줄, `require(`
- `fetch(` / `XMLHttpRequest`
- 외부 URL (cdnjs · fonts.googleapis · fonts.gstatic · `http://www.w3.org/` 네임스페이스만 허용)
- 문자열 안의 리터럴 `</scr` + `ipt` 시퀀스
- `TODO` / `FIXME` / `placeholder implementation` / `not implemented`

따라서 `mod-court.js` 는 이렇게 시작한다:

```js
/* =========================================================================
   MODULE: court  --  3D PHILOSOPHY COURTROOM + NOZICK RIG
   Declares: window.NZ.Court
   three.js r134 UMD (global THREE). No modules, no add-ons, no assets.
   ========================================================================= */
(function () {
  'use strict';
  var NZ = (window.NZ = window.NZ || {});
  var TH = (typeof THREE !== 'undefined') ? THREE : null;
  /* ... */
  NZ.Court = api;
})();
```

전역은 `window.NZ` 하나다. `Court` 는 `THREE` 를 참조하지만 **`ui.js` 는 `THREE` 를 절대 참조하지 않는다** — three.js가 통째로 없어도 UI가 죽지 않게 하기 위해서다.

### 1.3 3D 안에 문자를 넣지 않는다

캔버스에 어떤 글자·숫자도 그리지 않는다. `CanvasTexture` 에서도 `fillText` 를 호출하지 않는다.

- 칠판의 분필 자국은 **선과 빈 네모 도형**이다. "두 가지 조건"을 암시하는 그림이지 글자가 아니다.
- 사건 파일 더미는 **소품**이다. 사건 제목 10개는 DOM 로비 카드가 보여준다.
- 승인 도장 자국은 **빨간 링**이다. 한자도, `APPROVED` 도 찍지 않는다.

이유는 세 겹이다: 요구사항 §5가 금지하고, 크롬북 1366×768에서 3D 텍스처 텍스트는 안 읽히고, Google Fonts가 막힌 교실에서 한글이 두부로 나온다.

## 2. 화면 분할 — 어디가 3D이고 어디가 DOM인가

> **소유권.** DOM 골격·id·CSS 토큰·레이아웃 모드는 `02-화면흐름-상태기계.md` §7.2 와
> `04-레이아웃-접근성.md` §1 이 소유한다. **이 문서는 요소도 CSS 변수도 추가하지 않는다.**
> Court가 하는 일은 "주어진 캔버스 사각형 안에 구도를 만드는 것" 하나다.

### 2.1 캔버스 사각형이 곧 프레임이다

`#nz-gl` 은 뷰포트 전체를 덮지 않는다. 04 §1이 정한 대로 **화면 모드마다 다른 사각형**을 갖는다.

```css
/* 04-레이아웃-접근성.md §1 — 여기 적힌 것은 참조일 뿐, 소유자는 04다 */
#nz-gl{ position:fixed; top:var(--nz-hud-h); left:0; right:0; bottom:0; z-index:var(--nz-z-canvas); }
#nz-gl[data-split="1"]{ right:var(--nz-panel-w); }
@media (max-width:1023px){ #nz-gl[data-split="1"]{ right:0; bottom:auto; height:var(--nz-band-h); } }
```

| 04의 모드 | 조건 | 캔버스 사각형 | 1366×768 실측 | 캔버스 aspect |
|---|---|---|---|---|
| **overlay** | `data-screen` ∈ {`start`,`lobby`,`result`} | 전폭 × HUD 아래 전부 | 1366 × 720 | **1.90** |
| **split** | `case` + 폭 ≥ 1024 | 좌측 열 (`100vw − --nz-panel-w`) | 738 × 720 | **1.02** |
| **stack** | `case` + 폭 < 1024 | 전폭 × `--nz-band-h` | 900 × 215 | **4.19** |

`--nz-panel-w = clamp(492px, 46vw, 640px)` 이므로 split 캔버스의 aspect는 **0.74 ~ 1.24** 사이에서만 움직인다.
`--nz-band-h = min(28vh, 240px)` (599px 이하 `min(22vh,180px)`, 높이 559px 이하 **0px**).

**여기서 나오는 가장 중요한 결론:**

> **사건 화면(split·stack)에서는 3D와 DOM이 아예 겹치지 않는다.**
> 패널이 불투명한 별도 열이므로 대비 문제가 **구조적으로 존재하지 않는다.**
> 학생이 한국어 본문 2~3문장과 선택지 2개를 읽는 화면이 바로 이 화면이다.
> 겹침은 `start` · `lobby` · `result` 세 화면(overlay)에서만 생기고, 거기는 글자가 짧다.

내가 처음 설계했던 "전체화면 캔버스 + 좌측 38% 확보 + 밝은 재질 금지구역" 은 **폐기했다.**
04의 열 분할이 같은 문제를 더 싸게(렌더 픽셀 46% 감소) 그리고 더 확실하게(불투명 패널) 푼다.

### 2.2 리사이즈는 `ResizeObserver(#nz-gl)` 로만 듣는다

04 §11.3의 계약이다. **`window.resize` 를 듣지 않는다.**

```js
ro = new ResizeObserver(function () { layout(); });
ro.observe(canvas);
```

이유: `--nz-panel-w` 가 `clamp(…,46vw,…)` 이라 창 폭이 변하면 패널 폭이 변하고 캔버스 폭도 변하는데,
`data-split` 토글이나 `--nz-band-h` 미디어쿼리 전환은 **`window.resize` 없이도** 캔버스 사각형을 바꾼다.
`window.resize` 만 들으면 그 전환에서 캔버스가 늘어난 채로 남는다.

`ResizeObserver` 가 없는 환경(구형)이면 `window.resize` + `matchMedia` 두 개로 폴백하고,
`Court.resize()` 공개 메서드가 언제나 강제 갱신 경로로 남는다(§10).

캔버스 픽셀 크기는 Court가 정한다. **`canvas.style` 을 건드리지 않는다** — `setSize(w, h, false)` 의
세 번째 인자가 `false` 인 이유가 이것이다. CSS 크기의 주인은 04다.

### 2.3 세 개의 카메라 프리셋

단 하나의 `PerspectiveCamera`. 모드에 따라 위치·lookAt·FOV 락 방식이 바뀐다.
세트와 리그는 §3·§4 좌표 그대로 고정이고, `stage` 오프셋은 overlay에서만 쓴다.

| | **overlay** | **split** | **stack** |
|---|---|---|---|
| 쓰이는 화면 | start · lobby · result | case (≥1024) | case (<1024) |
| 구도 | 법정 전경. 노직은 좌측 | **흉상 + 벤치 + 칠판 일부.** 노직 중앙 | 머리·어깨 밴드 |
| `camera.position` | `(0.18, 1.46, 2.32)` | `(-0.78, 1.52, 2.05)` | `(-0.82, 1.55, 1.45)` |
| `lookAt` | `(-0.30, 1.27, 0.26)` | `(-1.00, 1.30, 0.22)` | `(-1.00, 1.42, 0.12)` |
| 거리 | 2.124 | 1.856 | 1.348 |
| FOV 락 | **가로 58°** | **가로 46°** | **세로 32°** |
| `stage.position.x` | `clamp(0, (1.45 − aspect)·0.62, 0.45)` | 0 | 0 |
| `stage.position.y` | 0 | 0 | 0 |

**FOV는 언제나 계산한다. 하드코딩하지 않는다.**

```js
var a = Math.max(0.35, w / h);                  /* 캔버스 aspect */
var fovY;
if (mode === 'stack') {
  fovY = 32;                                    /* 세로 락: 밴드 높이가 희소 자원이다 */
} else {
  var hf = (mode === 'split') ? 46 : 58;        /* 가로 락 */
  fovY = 2 * Math.atan(Math.tan(hf * Math.PI / 360) / a) * 180 / Math.PI;
}
cam.fov = Math.max(28, Math.min(54, fovY));
cam.aspect = a;
cam.updateProjectionMatrix();
```

**overlay와 split은 가로를 잠근다.** 가로 구도(노직이 화면의 어디쯤에 있는가)가 화면비와 무관하게 고정되고,
화면비가 바뀔 때 변하는 것은 위아래로 얼마나 더 보이느냐뿐이다. 이게 없으면 4:3 프로젝터에서 노직이 잘린다.

**stack만 세로를 잠근다.** 밴드는 가로가 남아돌고 세로가 모자란다(215px). 가로를 잠그면
세로가 0.1 m로 찌그러져 머리만 남고 도장도 지휘봉도 프레임 밖으로 나간다.

### 2.4 각 모드의 실측 구도

**overlay** — 1366×720 (aspect 1.90), fovY 32.5°

| | 값 |
|---|---|
| 프레임 가로 | x −1.477 ~ +0.877 (2.353 m) |
| 프레임 세로 | y 0.651 ~ 1.889 (1.238 m) |
| 노직 어깨 (x −1.30 ~ −0.70) | 좌측 **7.5% ~ 33%** |
| 정수리 (y 1.78) | 상단에서 **8.8%** |
| 벤치 상판 (y 1.075) | 상단에서 **66%** |

DOM 콘텐츠(시작 타이틀 / 로비 10장 / 결과)가 이 위에 `#nz-root::before` 스크림과 함께 얹힌다.
노직을 좌측 1/3에 두는 이유가 그것이다 — 중앙~우측이 DOM 자리다.

`stage.position.x` 식이 좁은 창을 구한다. aspect 1.90 → 0 / 1.10 → 0.217 / 0.79 → 0.409.
599px 폰 세로(aspect 0.79)에서는 fovY가 54°에 클램프되고 프레임 가로가 1.710 m로 좁아지는데,
스테이지를 0.409 밀어 넣어 노직을 화면 16% ~ 51% 자리로 되돌린다. 안 밀면 어깨가 왼쪽으로 잘린다.

**split** — 738×720 (aspect 1.02), fovY 45.2° ← **주 검증 구도**

| | 값 |
|---|---|
| 프레임 가로 | x −1.788 ~ −0.212 (1.576 m) |
| 프레임 세로 | y 0.528 ~ 2.073 (1.545 m) |
| 노직 어깨 | **31% ~ 69%** — 캔버스 열의 정중앙 |
| 정수리 | 상단에서 **19%** |
| 벤치 상판 | 상단에서 **64.5%** |
| 도장 (x −0.765) | 좌측 **65%** — 프레임 안 |
| 지휘봉 임팩트점 (x 약 −1.05) | 좌측 **47%** — 프레임 한복판 |

1024px(aspect 0.74)에서는 fovY가 54°에 클램프되어 세로로 더 보인다. 어깨는 여전히 중앙(28%~72%).
1920px(aspect 1.24)에서는 fovY 37.8°, 가로 구도는 **완전히 동일**(가로 락).

**stack** — 900×215 (aspect 4.19), fovY 32° 고정

| | 값 |
|---|---|
| 프레임 세로 | y 1.034 ~ 1.807 (0.773 m) |
| 프레임 가로 | 3.24 m — 좌우가 남아돈다 |
| 정수리 | 상단에서 **3.4%** |
| 벤치 상판 | 상단에서 **94.6%** |
| 어깨 (y 1.30) | 상단에서 **66%** |

세로 0.773 m 안에 정수리(1.78)부터 상판(1.075)까지 전부 들어간다.
도장이 찍히는 것도, 지휘봉이 상판을 치는 것도 밴드 맨 아래 가장자리에서 보인다.

**밴드 높이 가드.** `--nz-band-h` 는 `@media (max-height:559px)` 에서 **0px** 이 된다.

```js
if (h < 90) { renderer.setSize(Math.max(1, w), Math.max(1, h), false); paused = true; return; }
```

높이 90px 미만이면 렌더를 멈춘다. 0×0 캔버스에 `setSize` 를 부르면 r134가 경고를 뿜고,
그려봤자 아무것도 안 보이는 데 GPU를 쓴다. `data-three` 는 건드리지 않는다 — 실패가 아니라 **일시 정지**다.
화면이 커지면 `ResizeObserver` 가 다시 부르고 그대로 재개한다.

### 2.5 겹치는 유일한 곳 — overlay 모드의 대비

| 장치 | 내용 |
|---|---|
| 스크림 | `#nz-root::before` (04 §1 소유). 캔버스 위 딤 레이어 |
| 조명 방향 | key light가 왼쪽 위에서 온다. 화면 오른쪽은 구조적으로 어둡다 (§3.5) |
| Fog | `Fog(0x0b1024, 2.4, 5.2)`. 뒷벽(3.75 m)은 48%, 칠판(3.2 m)은 29% 배경색으로 눌린다. 노직(2.56 m)은 5.7%만 |
| 배치 | 밝은 재질(크림·황색·살색)은 **월드 x < −0.58** 에만. files · lamp · stamp · 손이 전부 만족한다 |

**검증:** `start` / `lobby` / `result` 각 화면을 1366×768로 캡처해 DOM 텍스트가 놓이는 영역의

## 3. 씬 구성

### 3.1 좌표계와 단위

- 1 단위 = **1 미터**. Y-up. 노직은 **+Z(카메라 쪽)를 향한다.**
- `rig.rotation.y = 0` — **몸은 돌리지 않는다.** 3/4 각은 카메라를 x +0.18 로 비껴 놓아서 만든다. 리그를 돌리지 않는 이유는 단 하나, 이 문서의 모든 월드 검증 좌표가 `rig.position + 로컬` 로 바로 떨어지게 하기 위해서다. 더 비스듬한 각이 필요하면 `rig.rotation.y` 를 ±0.12 안에서만 만지고, §4.4의 검증 좌표를 전부 다시 계산하라.

```
뒷벽 z −1.35  →  칠판 z −0.80  →  노직 z +0.06  →  벤치 상판 z +0.27  →  벤치 앞판 z +0.52  →  카메라 z +2.32
```

### 3.5 조명 — 4개 고정

```js
scene.add(new TH.AmbientLight(C.AMB, 0.55));

var key = new TH.DirectionalLight(C.KEY, 0.95);
key.position.set(-2.20, 3.00, 2.40);            /* 왼쪽 위 앞 */

desk.position.set(-1.78, 1.29, 0.12);           /* 은행가 램프 안 */
```

**라이트 개수는 절대 런타임에 바꾸지 않는다.** three.js는 라이트 수가 바뀌면 모든 재질의 셰이더를 다시 컴파일하고, 크롬북에서 그 스톨은 수백 ms다. 품질 단계는 **intensity만** 건드린다.

| 품질 | `key` | `rim` | `desk` |
|---|---|---|---|
| 2 | 0.95 | 0.35 | 0.55 |
| 1 | 0.95 | 0.28 | 0.45 |
| 0 | 0.95 | **0.18** | 0.30 |

`rim` 을 0으로 내리지 않는 이유는 §3.2에 적었다. 정장과 배경이 가까워서 rim이 실루엣의 유일한 분리 수단이다.

그림자: **`renderer.shadowMap.enabled = false`.** 셰도우맵은 드로우콜을 두 배로 만들고, 짙은 남색 방에서 얻는 그림은 거의 없다. 접지감은 벤치 상판 텍스처에 구운 부드러운 그라디언트가 대신한다(정적 메쉬에 포함되므로 비용 0).

| 이름 | 정의 | 쓰는 곳 |

### 4.4 대기 포즈 — 각도가 어디서 나왔는가

팔 각도는 손이 벤치 상판에 정확히 얹히도록 **역기구학을 손으로 풀어서** 구한 값이다. 근거를 남긴다. 상판을 옮기면 같은 절차로 다시 풀어야 한다.

**오른팔(지휘봉 쪽).** 목표: 손목이 torso 로컬 (−0.272, 0.246, 0.347) — 월드 (−1.272, 1.106, 0.407). 손바닥 바닥이 y 1.073, 상판 1.075에 닿는다.

```
어깨 → 손목 벡터 d = (0.067, -0.194, 0.342),  |d| = 0.399
상완 a = 0.240,  전완 b = 0.235
팔꿈치 내각 = acos((a²+b²-|d|²)/(2ab)) = 114.2°  →  굽힘 65.8° = 1.149 rad
상완이 d에서 벌어지는 각 α = asin(b·sin(114.2°)/|d|) = 32.5°
```

→ **`armR.rotation = (−0.477, 0, −0.200)`, `elbowR.rotation.x = −1.149`**
(Euler 'XYZ'. `rotation.z` 는 바깥으로 벌리는 각. 오른팔은 −X 쪽이 바깥이므로 음수.)

**왼팔(도장 쪽).** 도장 손잡이를 쥐어야 하므로 손목이 오른손보다 **0.10 높다**: torso 로컬 (0.235, 0.345, 0.352), 월드 (−0.765, 1.205, 0.412).

```
d = (0.030, -0.095, 0.347), |d| = 0.361
팔꿈치 내각 98.9°  →  굽힘 81.1° = 1.416 rad,   α = 40.0°
```

→ **`armL.rotation = (−0.600, 0, +0.110)`, `elbowL.rotation.x = −1.416`**

**부호 규약** (틀리면 팔이 뒤로 간다):

| 조인트 | 양수 방향 |
|---|---|
| `torso.rotation.x` | **앞으로 숙임** (윗몸이 +Z = 카메라 쪽으로) |
| `torso.rotation.y` | 화면 오른쪽으로 몸 틀기 |
| `head.rotation.x` | **고개 숙임** (얼굴이 아래로) |
| `head.rotation.y` | 화면 오른쪽 보기 |
| `arm*.rotation.x` | **뒤로.** 앞으로 뻗으려면 **음수** |
| `arm*.rotation.z` | +X 쪽으로 벌리기 (오른팔은 음수가 바깥) |
| `elbow*.rotation.x` | 음수가 굽힘 |
| `brow*.rotation.z` | `browL` 양수 = 찡그림 (§4.2) |

**검증 스니펫.** 리그를 다 만든 뒤 반드시 콘솔에서 돌린다.

```js
var p = new THREE.Vector3();
rig.handR.getWorldPosition(p);   /* 기대 (-1.272, 1.106, 0.407) ± 0.02 */
rig.handL.getWorldPosition(p);   /* 기대 (-0.765, 1.205, 0.412) ± 0.02 */

/* idle 기대: y 1.10 ± 0.03, z 0.30 ± 0.05, x -1.15 ± 0.08 */
```

지휘봉 팁이 안 맞으면 **팔 각도를 건드리지 말고 `batonR.rotation.x` 부터 조정하라.** 팔 각도는 손이 상판에 놓이도록 이미 풀려 있고, 팁 위치는 손 안에서의 지휘봉 기울기가 결정한다. 조정 구간은 −1.05 ~ −1.35.

## 5. 세 가지 상태 — 키프레임 타임라인

### 5.0 타임라인의 평가 방식

타임라인은 **절대 포즈의 나열이 아니라 `from → to` 보간**이다. `setMood()` 가 호출되는 순간의 모든 조인트 현재값을 `from` 으로 스냅샷하고, 각 키프레임은 `to` 를 준다. 이렇게 해야 애니메이션 도중에 다른 mood가 들어와도 튀지 않는다(§6).

이징:

```js
function clamp01(v) { return v < 0 ? 0 : (v > 1 ? 1 : v); }
function lerp(a, b, t) { return a + (b - a) * t; }
function smooth(t) { t = clamp01(t); return t * t * (3 - 2 * t); }        /* 기본 */
function easeIn(t)  { t = clamp01(t); return t * t; }                     /* 가속 하강 */
function easeOut(t) { t = clamp01(t); return 1 - (1 - t) * (1 - t) * (1 - t); }  /* 복귀 */
```

`smooth` / `lerp` / `clamp` 는 `SR2/src/mod-worldB.js:153-155` 와 동일한 구현이다. 저장소 관례를 따른다.

### 5.1 idle — 대기 (무한 루프)

읽는 시간이다. **산만하면 실패다.** 카메라는 idle에서 **절대 움직이지 않는다** — 학생이 DOM 패널의 한국어 3문장과 선택지 2개를 읽는 동안 배경이 흔들리면 안 되기 때문이다.

### 5.4 변주 — 연속 오답의 반복감 줄이기

```js
  if (streak >= 3) return 3;                       /* 강제: 제일 조용한 변주 */
```

## 6. 전이 규칙

### 6.1 애니메이션 중 다른 요청이 들어오면

```
setMood(next) 호출
  ├ next === 현재 mood 이고 opts.variant 가 명시되지 않았다 → 무시하고 리턴
  ├ 그 외
  │   1. 모든 조인트의 현재 값을 fromPose 로 스냅샷
  │   2. 0.12 s 동안 fromPose → next 타임라인의 t=0 포즈 로 smooth 크로스페이드
  │   3. 크로스페이드가 끝나면 next 타임라인을 t=0 부터 재생
  └ 잔존 오브젝트(inkRing opacity, files.position.y, key.intensity, stage.position.z)는
    크로스페이드 시작과 동시에 기본값으로 0.12 s 복귀
```

`'idle'` 로의 전이만 예외적으로 **0.35 s `easeOut`** 이다. 승인·반박 뒤에 idle로 툭 끊기면 인형이 되고, 0.35 s면 "동작을 마치고 자세를 고쳐 잡는" 것으로 읽힌다.

### 6.2 '다음 사건' 버튼

**UI는 3D를 기다리지 않는다.** `setMood()` 는 완료 콜백도, Promise도 반환하지 않는다. 의도적이다.

```js
/* ui.js — 다음 사건 핸들러 */
function onNext() {
  state.goNextUnanswered();      /* 1. 상태부터 */
  render();                      /* 2. DOM부터 */
  NZ.Court.setMood('idle');      /* 3. 3D는 알아서 따라온다 */
}
```

반박 애니메이션이 0.4 s 진행된 상태에서 학생이 '다음'을 눌렀다면, DOM은 즉시 다음 사건을 그리고 3D는 0.12 s 크로스페이드 + 0.35 s 복귀로 정리된다. 학생은 기다리지 않는다.

> **금지: `setMood` 의 완료를 기다렸다가 버튼을 활성화하는 코드.** 3D가 죽었거나(폴백) 탭이 백그라운드였으면 그 버튼은 영원히 안 켜진다. 5분짜리 수업 도입에서 그건 치명적이다.

### 6.3 중복 채점 방지와의 관계

요구사항 §3은 "답을 고르면 즉시 입력을 잠가 중복 채점을 막는다"고 했다. **그 잠금은 상태 모듈이 하는 것이지 Court가 하는 게 아니다.** Court는 잠금 상태를 읽지도 쓰지도 않는다. 애니메이션 길이와 입력 잠금 시간을 연결하지 마라 — 연결하는 순간 3D 실패가 게임 정지가 된다.

### 6.4 `pulse()` 의 전이

`pulse()` 는 mood를 **바꾸지 않는다.** 현재 타임라인 위에 얹히는 0.25 s짜리 가산 효과다.

| t (s) | 값 |
|---|---|
| 0.00 → 0.10 | `head.rotation.y` += +0.030, 눈썹 += (−0.06, +0.06), glint `emissiveIntensity` 0 → 0.55 |
| 0.10 → 0.25 | 전부 0으로 `easeOut` |

쿨다운 **0.40 s.** 쿨다운 중의 호출은 조용히 무시한다(사건 카드 연타 방어).

### 7.2 그림자와 후처리

- **그림자: 끈다.** `renderer.shadowMap.enabled = false`. 켜면 드로우콜이 두 배가 되고, 짙은 남색 방에서 얻는 그림이 거의 없다.

- 접지감은 벤치 상판에 구운 부드러운 그라디언트가 낸다 — 정적 메쉬에 합쳐지므로 추가 비용 0.

### 7.3 pixelRatio 사다리

04 §1이 **모드별 DPR 상한**을 이미 정해 두었다: 분할 `min(dpr, 1.5)`, 오버레이 `min(dpr, 1.25)`.
품질 사다리는 그 **아래로만** 움직인다 — 둘 중 작은 값을 쓴다.

```js
var DPR      = [1.00, 1.25, 1.50];              /* quality 0 / 1 / 2 */
var MODE_CAP = { overlay: 1.25, split: 1.50, stack: 1.50 };   /* 04 §1 */

function applyQuality(q) {
  var w = canvas.clientWidth, h = canvas.clientHeight;
  var dpr = Math.min(window.devicePixelRatio || 1, DPR[q], MODE_CAP[mode]);
  if (w * h * dpr * dpr > 2200000) dpr = Math.sqrt(2200000 / (w * h));
  renderer.setPixelRatio(Math.max(0.5, dpr));
  rim.intensity  = [0.18, 0.28, 0.35][q];
  desk.intensity = [0.30, 0.45, 0.55][q];
  idleHz         = [20, 30, 30][q];
}
```

**overlay가 1.25로 더 낮은 이유는 04가 적어 두었다** — 오버레이 모드에서는 캔버스가 전폭이라
렌더 픽셀이 split의 약 1.9배다. 그런데 오버레이 화면(start·lobby·result)은 애니메이션이
idle 하나뿐이라 해상도를 내려도 잃는 것이 거의 없고, split은 반응 연출이 벌어지는 화면이라 선명해야 한다.

**Court는 CSS 클래스를 쓰지 않는다.** 품질 단계는 렌더러 내부 상태일 뿐이고,
`html` 이나 `#nz-root` 에 `nz-q*` 같은 클래스를 붙이지 않는다 — DOM 속성의 주인은 02·04다.
품질 값이 필요하면 `_probe().quality` 로 읽는다.

초기 단계:

```js
var q = 1;
if ((window.devicePixelRatio || 1) > 1.5 && window.innerWidth >= 1280) q = 2;
if ((navigator.hardwareConcurrency || 4) <= 2) q = 0;
```

**품질 단계가 바뀌어도 지오메트리는 절대 다시 만들지 않는다.** 재생성은 GC 스톨을 부르고, 그 스톨이 곧 "프레임이 떨어졌다"는 다음 샘플을 만들어 사다리를 바닥까지 끌고 내려간다.

### 7.4 자동 사다리

`SR2/src/02-director.js` 의 `Perf` 와 같은 규칙이다. 검증된 것을 다시 쓴다.

```js
var acc = 0, n = 0, cool = 0;
function sample(dt) {
  acc += dt; n++; cool -= dt;
  if (n < 45) return;
  var avg = acc / n; acc = 0; n = 0;
  if (cool > 0) return;
  if (avg > 1 / 26 && quality > 0) { quality--; applyQuality(quality); cool = 3; }
  else if (avg < 1 / 55 && quality < 2) { quality++; applyQuality(quality); cool = 6; }
}
```

- **컨텍스트 소실 중에는 샘플링하지 않는다.** 그 프레임들은 이 GPU에 대한 증거가 아니고, 증거로 읽으면 수업 내내 최저 품질에 갇힌다.
- **탭이 숨겨진 직후 첫 프레임도 샘플링하지 않는다.** `dt` 가 몇 초짜리로 들어온다. 복귀 시 `lastFrame = 0` 으로 리셋한다.
- **`antialias` 는 내릴 수 없다.** 컨텍스트 생성 시점에만 정해지는 값이라 품질 0에서도 켜진 채다. 정직하게 적어둔다 — 사다리의 실제 레버는 `pixelRatio` 하나다.

### 7.5 화면이 안 보일 때 렌더를 멈춘다

| 신호 | 동작 |
|---|---|
| `document.hidden === true` (`visibilitychange`) | rAF 루프 중단. 복귀 시 `lastFrame = 0` |
| `IntersectionObserver` 로 캔버스가 뷰포트 밖 | rAF 루프 중단 |
| `mood === 'idle'` 이고 0.6 s 이상 유지 | **`idleHz` 로 스로틀** (품질 2·1 → 30 fps, 품질 0 → 20 fps). `setMood` / `pulse` 가 오면 즉시 60 fps 복귀 |
| `prefers-reduced-motion` + idle | **15 fps** 로 스로틀 |

스로틀 구현은 프레임을 건너뛰는 것이지 rAF를 끄는 게 아니다:

```js
function frame(now) {
  rafId = requestAnimationFrame(frame);
  var dt = lastFrame ? (now - lastFrame) / 1000 : 0.016;
  if (throttleHz && (now - lastDraw) < (1000 / throttleHz) - 1) return;
  lastDraw = now; lastFrame = now;
  tick(dt > 0.1 ? 0.1 : dt);
}
```

**idle을 완전히 정지시키지는 않는다.** 호흡과 안경 glint이 멈추면 학생이 "화면이 멈췄다"고 읽고 손을 든다. 5분 수업에서 그 한 번의 손이 진행을 통째로 끊는다. 20 fps짜리 호흡은 충분히 살아 있어 보인다.

## 8. `prefers-reduced-motion`

### 8.1 구독

`SR2/src/mod-fx.js:30` 패턴을 그대로 쓴다. 폴링하지 않고 캐시 + `change` 리스너.

```js
var reduced = false;
(function () {
  try {
    if (!window.matchMedia) return;
    var mq = window.matchMedia('(prefers-reduced-motion: reduce)');
    reduced = !!mq.matches;
    var h = function () { reduced = !!mq.matches; };
    if (mq.addEventListener) mq.addEventListener('change', h);
    else if (mq.addListener) mq.addListener(h);
  } catch (e) { reduced = false; }
})();
```

### 8.3 왜 의미가 안 줄어드는가

**승인과 반박의 구분은 진폭이 아니라 두 가지가 전달한다:**

1. **눈썹 각도** — approve −0.13 / rebut +0.30. 부호가 반대다. 진폭을 줄이지 않는다.
2. **소품** — approve에는 도장이 내려오고 빨간 링이 남는다. rebut에는 지휘봉이 올라갔다 내려온다. 움직임의 *크기*가 아니라 *어떤 물건이 관여하는가*가 다르다.

그래서 reduced 모드에서 카메라 킥을 완전히 제거하고 스윙을 절반으로 줄여도 **두 상태의 구분은 100% 살아남는다.** 리그를 이렇게 설계한 이유가 이것이다.

게다가 DOM 패널이 이미 색 외의 신호(아이콘 + "노직의 예상 답과 일치/불일치" 문장 + 영어 개념어)를 주므로, 3D는 어느 모드에서도 **보조 채널**이다. 3D가 통째로 없어도 정보 손실이 0이어야 한다 — 그게 §9가 성립하는 근거다.

## 9. WebGL 실패 · 컨텍스트 소실 → 2D 폴백

요구사항 §6·§8: *"WebGL 사용 불가나 3D 초기화 실패 시에도 2D 대체 화면으로 10개 사건을 모두 풀 수 있게 한다."*

> **스위치의 소유자는 02다.** `#nz-root[data-three="on"|"off"]` (02 §7.3).
> 04 §12: *"레이아웃은 바뀌지 않는다. 열 비율·패널·키맵·세로 예산은 전부 동일하다."*
> Court는 그 계약을 지킨다 — 폴백은 **캔버스가 차지하던 사각형 안에서만** 일어난다.

### 9.1 감지 신호 7가지

| # | 신호 | 시점 | 처리 |
|---|---|---|---|
| 1 | `typeof THREE === 'undefined'` 또는 `!THREE.WebGLRenderer` | init 진입 즉시 | `init` → `false` |
| 2 | **오프스크린 프로브 실패** — 별도 `<canvas>` 에서 `getContext('webgl')` / `'experimental-webgl'` 가 둘 다 null | init, 렌더러 생성 **전** | `init` → `false` |
| 3 | `webglcontextcreationerror` 이벤트 | 렌더러 생성 **전에** 리스너를 붙여야 잡힌다 | 플래그 → `init` → `false` |
| 4 | `new THREE.WebGLRenderer(...)` 가 throw | init | catch → `init` → `false` |
| 5 | `renderer.getContext()` 가 null | 생성 직후 | `init` → `false` |
| 6 | **3초 워치독** — `document.hidden === false` 이고 캔버스 높이 ≥ 90px 인데 3 s 동안 그려진 프레임이 0 | 런타임 | 폴백 전환 |
| 7 | `webglcontextlost` → `preventDefault()` → **12 s 안에 `restored` 없음** | 런타임 | 폴백 **영구** 전환 |

프로브는 **반드시 별도 캔버스**로 돌리고 끝나면 컨텍스트를 반납한다.
실제 캔버스에서 프로브하면 그 컨텍스트가 점유되어 렌더러 생성이 실패한다.

```js
function probeWebGL() {
  try {
    var c = document.createElement('canvas');
    var gl = c.getContext('webgl') || c.getContext('experimental-webgl');
    if (!gl) return false;
    var ext = gl.getExtension('WEBGL_lose_context');
    if (ext) ext.loseContext();
    return true;
  } catch (e) { return false; }
}
```

### 9.2 전환 동작

```js
function goFallback() {
  if (fallback) return;
  fallback = true;
  api.ok = false;
  if (canvas) canvas.hidden = true;                    /* 검은 사각형이 남지 않게 */
  var root = document.getElementById('nz-root');
  if (root) root.setAttribute('data-three', 'off');    /* 02 §7.3 의 스위치 */
  if (bust) bust.hidden = false;
  applyFallbackMood(mood, variant);                    /* 진행 중이던 상태를 그대로 이어받는다 */
}
```

- **`data-three` 를 쓰는 주체가 둘이다.** 부팅 시엔 `main.js` 가 `Court.init()` 반환값으로 쓰고(02 §9),
  런타임 소실 시엔 Court가 쓴다. **둘 다 같은 속성에 같은 값을 쓰므로 멱등이다.**
  Court가 쓰지 않으면 컨텍스트 소실 때 아무도 안 쓴다 — 소실을 아는 모듈이 Court뿐이기 때문이다.
- 컨텍스트가 **복구되면** `data-three="on"` 으로 되돌리고 캔버스를 다시 보인다. 진행 중이던 mood는 이어진다.
- 게임 상태(`NZ.State`)는 이 전환을 전혀 모른다. Court는 State를 읽지도 쓰지도 않는다.

### 9.4 노직 — 요소 하나

폴백에도 노직이 있어야 한다(요구사항 §5: 3상태가 시각적으로 구분되어야 한다).
`::before` 로는 관절을 못 만들므로 **요소 하나**를 쓴다.

```
<svg id="nz-fb-bust" aria-hidden="true" hidden viewBox="0 0 220 260">   ← #nz-gl 의 형제
```

- **소유자는 court3d.js다.** ui.js는 이 요소를 읽지도 쓰지도 않는다(02 §7.1의 모듈 분리 유지).
- `#nz-gl` 과 **같은 사각형** 안에 위치한다(`position:fixed`, 같은 `top/left/right/bottom` 규칙).
  따라서 04 §12의 "레이아웃은 바뀌지 않는다"가 그대로 성립한다 — 열 비율·패널·키맵·세로 예산 전부 동일.
- `data-three="on"` 일 때는 `hidden`. 04의 전역 `[hidden]{display:none!important}` 가 처리한다.
- 원·타원·사각형만. 약 60줄. 외부 파일 없음, `fetch` 없음.

```
<g id="fbBody">                     몸통 · 어깨
  <g id="fbArmR"> 팔 + 손 + <g id="fbBaton"> 지휘봉 </g> </g>
  <g id="fbArmL"> 팔 + 손 </g>
  <g id="fbHead">                   머리 · 머리카락 · 귀 · 코
    <g id="fbBrows"> <rect id="fbBrowL"/> <rect id="fbBrowR"/> </g>
    <g id="fbEyes">  <ellipse/> x2
    <g id="fbGlass"> <circle/> x2 + bridge + <rect id="fbGlint"/> </g>
  </g>
</g>
<g id="fbStamp"> 도장 </g>

```

`transform-origin` 을 각 그룹에 명시한다. 기본값(`view-box`)이면 회전 중심이 SVG 원점이 되어 머리가 궤도를 그린다.

```css

#fbBrowL { transform-box:fill-box; transform-origin:100% 50%; }  /* 바깥 끝 — §4.2와 같은 규약 */
#fbBrowR { transform-box:fill-box; transform-origin:0% 50%; }
```

### 9.5 3상태 — 포즈는 `transition`, 장식만 `animation`

**이게 이 절에서 제일 중요한 규칙이다.**

04 §9.1은 모션 감소에서 전역으로 이렇게 건다:

```css
*,*::before,*::after{ animation-duration:1ms!important; animation-iteration-count:1!important; }
```

`!important` 전역 규칙이라 **내 SVG의 keyframe은 예외 없이 죽는다.**
따라서 **상태 구분을 `animation` 에 실으면 모션 감소에서 승인과 반박이 똑같아진다.**

그래서 계층을 나눈다:

| 계층 | 수단 | 모션 감소에서 |
|---|---|---|
| **포즈** (의미) | 클래스가 바꾸는 `transform` / `opacity` 값 + `transition` | **살아남는다.** 04는 `transition-duration:var(--nz-t-base)` = 90ms 로 줄일 뿐 없애지 않는다 |
| **장식** (호흡·glint·깜빡임) | `@keyframes` + `animation` | 죽어도 무방. 의미를 하나도 안 싣는다 |

| 상태 | 클래스 | **포즈** (transition, 의미) | **장식** (animation) |
|---|---|---|---|
| **idle** | `.is-idle` | 눈썹 수평(`rotate(0)`), 지휘봉 `rotate(-34deg)`, 도장 `translateY(0)`, 잉크 `opacity:0` | `#fbBody` 호흡 4.0s · `#fbEyes` 깜빡임 4.4s · `#fbGlint` 9s |
| **approve** | `.is-approve` | `#fbHead` `rotate(6deg)` · `#fbBrows` `translateY(-3px)` · `#fbStamp` `translateY(0) scaleY(.88)` · `#fbInk` `opacity:.9; r:14` | 없음 |
| **rebut** | `.is-rebut` | `#fbBaton` `rotate(8deg)` · `#fbBrowL` `rotate(14deg)` / `#fbBrowR` `rotate(-14deg)` · `#fbHead` `rotate(4deg)` | `#fbBody` 좌우 흔들림 (모션 감소에서 죽어도 무방) |
| **pulse** | `.is-pulse` 260ms | `#fbHead` `rotate(3deg)` | `#fbGlint` 1회 |

타이밍은 3D 타임라인과 같은 시각에 맞춘다: approve는 0 → 0.22 s 들어올림, 0.22 → 0.38 s 내려침,
0.38 s에 도장 도달 + 잉크 등장, 0.85 s에 `.is-approve` 제거. rebut은 0.30 s에 지휘봉 도달,
0.70 s에 눈썹 복귀, 1.05 s에 `.is-rebut` 제거.

```css
#fbHead,#fbBrows,#fbBaton,#fbStamp,#fbInk,#fbBrowL,#fbBrowR{
  transition: transform var(--nz-t-slow) ease-out, opacity var(--nz-t-slow) ease-out;
}
```

**클래스는 `animationend` 가 아니라 JS 타이머로 뗀다.** `animationend` 는 백그라운드 탭에서 안 오고,
모션 감소에서는 1ms 만에 와 버린다. 둘 다 노직을 잘못된 포즈에 굳힌다.

### 9.6 폴백에서도 10개 사건이 전부 풀린다

게임 로직이 3D를 **한 줄도** 참조하지 않기 때문이다.

- `Court.ok === false` 여도 `setMood` / `pulse` / `resize` 는 **전부 호출 가능하고 전부 동작한다.**
  no-op가 아니라 SVG 클래스를 토글한다.
- `setMood()` 는 폴백에서도 **정확한 ms 숫자**를 반환한다(§10). 02 §7.5가 못 박은 조건이다 —
  `undefined` 를 반환하면 `setTimeout(fn, undefined)` 가 되어 피드백이 **즉시** 열리고 반응 연출이 통째로 사라진다.
- 저장·점수·완료 목록·최초 선택은 Court가 읽지도 쓰지도 않는다.

**검증 (요구사항 §8 / 02 §10 체크리스트와 동일 항목):**

```js
document.getElementById('nz-root').setAttribute('data-three', 'off');
NZ.Court.dispose();
/* → 10개 사건을 전부 풀고 결과 화면까지 도달하는지 수동 플레이로 확인 */
/* → DevTools 에서 prefers-reduced-motion 을 켠 채로 한 번 더:
      승인과 반박이 여전히 구분되는가? (§9.5의 포즈/장식 분리가 여기서 증명된다) */
```

## 10. `window.NZ.Court` — 정확한 API

`ui.js` 구현자는 이 절만 읽으면 된다.

```js
/**
 * @typedef {'idle'|'approve'|'rebut'} NZMood
 * @typedef {Object} NZMoodOpts
 * @property {number}  [seed=0]        사건 인덱스 0~9. 변주 선택에 쓰인다
 * @property {number}  [streak=0]      연속 오답(rebut) 또는 연속 정답(approve) 수
 * @property {number}  [variant=null]  변주 강제 지정. 테스트용
 * @property {boolean} [hold=false]    true면 종료 후 idle로 자동 복귀하지 않는다
 */
window.NZ.Court = {
  ok: false,
  init:    function (canvasEl) { return false; },   /* -> boolean */
  setMood: function (mood, opts) { return 0; },     /* -> number (ms) */
  pulse:   function () {},                          /* -> void */
  resize:  function () {},                          /* -> void */
  dispose: function () {}                           /* -> void */
};
```

### `ok` — boolean, 읽기 전용

`init()` 전에는 `false`. 3D가 뜨면 `true`. 폴백으로 전환되면 다시 `false`.

**UI는 이 값을 분기에 쓸 필요가 없다.** 폴백도 Court가 처리한다(§9.6).
`main.js` 가 `data-three` 를 쓰기 위해 한 번 읽는 것(02 §9)과 진단용이 전부다.

### `init(canvasEl)` → `boolean`

| | |
|---|---|
| 인자 | `HTMLCanvasElement`. `null`/생략이면 `document.getElementById('nz-gl')` 을 찾는다. 못 찾으면 `false` |
| 반환 | `true` = 3D 가동, `false` = 폴백. **`false` 여도 Court는 계속 쓸 수 있다** |
| 동기/비동기 | **동기.** Promise가 아니다. 리턴 시점에 렌더러·씬·리그·옵저버·rAF 루프가 전부 준비돼 있다 |
| 재호출 | 두 번째부터는 아무 일도 하지 않고 현재 `ok` 를 반환 |
| 예외 | **절대 throw하지 않는다.** 전체가 try/catch |

부작용:

- `#nz-gl` 의 형제로 `<svg id="nz-fb-bust" hidden>` 를 삽입(§9.4). **Court가 소유한다.**
- `ResizeObserver(#nz-gl)` 구독. `document` 에 `visibilitychange`,
  `canvas` 에 `webglcontextlost`·`webglcontextrestored`·`webglcontextcreationerror`,
  `matchMedia('(prefers-reduced-motion: reduce)')` 에 `change`.
- **`data-three` 는 부팅 시점에 쓰지 않는다.** `main.js` 가 반환값을 보고 쓴다(02 §9).
  Court가 이 속성을 쓰는 것은 **런타임 컨텍스트 소실·복구 때뿐**이다(§9.2).
- **`canvas.style` · `--nz-*` 변수 · 레이아웃 관련 CSS를 건드리지 않는다.** 그건 04의 소유다.

내부 순서:

```
1. reduced-motion 구독
2. probeWebGL()                — 별도 캔버스, 끝나면 반납
3. canvas 에 webglcontextcreationerror 리스너   ← 렌더러 생성 전에!
4. 렌더러 생성 (§3.7)
5. 씬 · 세트 · 리그 · 조명 · 소품 구축
6. SVG 흉상 삽입 (hidden) · ResizeObserver · 나머지 리스너
7. layout() 1회
8. rAF 루프 시작, mood = 'idle'
9. ok = true
   — 2~5 중 어디서든 실패하면 goFallback() 후 false 반환
```

### `setMood(mood, opts)` → `number` (밀리초)

| | |
|---|---|
| `mood` | `'idle'` / `'approve'` / `'rebut'`. 그 외 문자열은 조용히 무시하고 `0` 반환 — **콘솔 경고를 찍지 않는다.** 수업 중 콘솔 노이즈 금지 |
| `opts.seed` | number, 기본 0. 정수 강제, 음수는 abs. 사건 인덱스를 그대로 넣으면 된다 |
| `opts.streak` | number, 기본 0. **rebut에서 3 이상이면 조용한 변주로 강제** (§5.4) |
| `opts.variant` | number 또는 null, 기본 null. 지정하면 seed/streak 계산을 건너뛴다 |
| `opts.hold` | boolean, 기본 false. true면 타임라인 종료 후 마지막 포즈를 유지 |
| 같은 mood 재호출 | 재생하지 않고 **남은 시간**을 반환. 단 `variant` 가 명시되면 재생 |
| 재생 중 다른 mood | 0.12 s 크로스페이드 후 새 타임라인 (§6.1) |
| `ok === false` | **여전히 유효하다.** SVG 폴백 클래스를 토글하고 같은 숫자를 반환 |

**반환값 — 이 반응이 끝나는 데 걸리는 밀리초.**

| 조건 | 반환 |
|---|---|
| `'approve'` 기본 | `850` |
| `'approve'` 모션 감소 | `700` |
| `'rebut'` v0 | `1050` · v1 `1100` · v2 `1150` · v3 `950` |
| `'rebut'` 모션 감소 | 위 값 그대로 (§8은 **길이가 아니라 진폭**을 줄인다) |
| `'idle'` | `0` |
| 알 수 없는 mood · 3D 실패 · 폴백 | 해당 mood의 같은 숫자. **절대 `undefined` 를 반환하지 않는다** |

> 02 §7.5가 못 박은 조건이다. `undefined` 를 반환하면 `setTimeout(fn, undefined)` 가 되어
> 피드백이 안 열리는 게 아니라 **즉시 열려버려 반응 연출이 통째로 사라진다.**
> 그래서 `0` 을 반환하는 경우도 `'idle'` 하나뿐이고, 나머지는 전부 실제 길이다.

**이 숫자는 타이머용이지 완료 콜백이 아니다.** 02 §4.3의 T9가 쓰는 값이다:

```js
var ms = NZ.Court.setMood(r.match ? 'approve' : 'rebut',
                          { seed: caseIndex, streak: streak });
setTimeout(toFeedback, ms);      /* T9 */
```

Court는 Promise도, 완료 이벤트도, `onDone` 콜백도 제공하지 않는다. **의도적이다.**
콜백은 "3D가 끝나야 UI가 움직인다"는 결합을 만들고, 3D가 죽거나 탭이 백그라운드면 그 콜백은 오지 않는다.
숫자는 미리 알 수 있고, 미리 알 수 있는 값은 3D가 죽어도 정확하다.

> **모션 감소에서 `0` 을 반환하지 않는 이유.** 02 §9는 모션 감소에서 `react()` → `0ms` 를 적어 두었지만,
> 그러면 **선택하는 순간 피드백이 튀어나와** 노직이 반응했다는 사실 자체가 사라진다.
> §8에서 보였듯 모션 감소는 **진폭**을 줄이는 것이지 반응을 없애는 것이 아니다 — 눈썹 각도와
> 도장/지휘봉은 그대로 남는다. approve만 850→700 ms로 줄이고 rebut은 길이를 유지한다.
> **이 한 항목은 02와 다르다. §13에 충돌로 올려 두었다.**

### `pulse()` → `void`

0.25 s짜리 주목 반응. **mood를 바꾸지 않는다.** 쿨다운 0.40 s, 쿨다운 중 호출은 무시.

용도: 로비 사건 카드 포커스/호버, 선택지 포커스 이동, 결과 화면 진입.
폴백: `#nz-fb-bust` 에 `.is-pulse` 를 260 ms 부착.

### `resize()` → `void`

**평소에는 부를 필요가 없다.** Court가 `ResizeObserver(#nz-gl)` 로 스스로 잡는다(§2.2, 04 §11.3).

직접 부를 때: `ResizeObserver` 가 없는 구형 브라우저, 전체화면 토글 직후,
그리고 테스트에서 강제 갱신이 필요할 때.

하는 일:

```
1. canvas.clientWidth / clientHeight 읽기
2. 높이 < 90px  →  paused = true, 렌더 중단하고 리턴 (밴드 높이 0 대응, §2.4)
3. renderer.setSize(w, h, false)        ← false: CSS 크기를 건드리지 않는다
4. 모드 판정 — NZ.layout.mode() 와 #nz-root[data-screen] 으로 overlay/split/stack
5. 카메라 프리셋 적용 + FOV 락 계산 (§2.3)
6. stage.position.x 계산 (overlay 전용)
7. applyQuality(quality)                ← 모드별 DPR 상한 재적용 (§7.3)
```

### `dispose()` → `void`

```
1. cancelAnimationFrame
2. ResizeObserver.disconnect() · 모든 리스너 해제 (visibilitychange / contextlost /
   contextrestored / contextcreationerror / matchMedia change)
3. 모든 geometry · material · texture 의 .dispose()
4. renderer.dispose(); renderer.forceContextLoss()      ← r134에 존재
5. #nz-fb-bust 제거, canvas 참조 해제, scene 비우기
6. ok = false
```

`data-three` 는 건드리지 않는다 — 그 속성의 주인은 `main.js` 다(02 §9).
`dispose()` 뒤에 `init()` 을 다시 부르면 되살아난다.
이 게임은 한 번 열고 끝이므로 사실상 개발·테스트용이지만 **반드시 구현한다**:
`init()`/`dispose()` 20회 반복에 컨텍스트가 새지 않는 것이 기본 검증 항목이다.

### 부작용 — DOM 이벤트

Court는 **소리를 내지 않는다.** 임팩트 순간에 `document` 로 이벤트를 던진다.

```js
document.dispatchEvent(new CustomEvent('nz:impact', { detail: { mood: 'approve', variant: 0 } }));
```

| mood | 디스패치 시각 |
|---|---|
| `approve` | 타임라인 **0.38 s** |
| `rebut` (v0·v1) | 타임라인 **0.30 s** |
| `rebut` (v2) | **0.30 s** 와 **0.48 s**, 두 번 |
| `rebut` (v3) | **디스패치하지 않는다** (조용한 변주) |

`sfx.js` 가 있으면 듣고, 없으면 아무 일도 안 일어난다. 메서드를 늘리지 않고 소리와 시각을 프레임 단위로 붙이는 방법이다.
효과음 기본값은 OFF다(요구사항 §5).

### 02 §7.5 호환 어댑터 — 같은 모듈 안 8줄

`02-화면흐름-상태기계.md` 는 다른 이름의 API를 적어 두었다. **핵심 6개는 위가 전부이고,**
02의 이름들은 그 위에 얹는 얇은 래퍼로 만든다. 두 문서가 한 구현으로 동시에 만족된다.

| 02의 호출 | 핵심 API로의 매핑 |
|---|---|
| `react('match', id)` → ms | `setMood('approve', { seed: idx(id), streak: correctStreak })` |
| `react('miss', id)` → ms | `setMood('rebut', { seed: idx(id), streak: wrongStreak })` |
| `setPose('approve')` | `setMood('approve', { hold: true, variant: 0 })` 후 즉시 타임라인 끝으로 점프 |
| `setPose('object')` | `setMood('rebut', { hold: true, variant: 3 })` 후 끝으로 점프 (**조용한 변주** — 재방문에 타격음 반복 금지) |
| `setPose('idle')` / `idle()` | `setMood('idle')` |
| `setScene(screen)` | 모드 재판정 + `resize()`. `'lobby'` 진입 시 `pulse()` |
| `setReducedMotion(on)` | 내부 `matchMedia` 구독값을 덮어쓰는 수동 오버라이드 |
| `highlightFile(id)` / `setFiles(list)` / `nz:anchors` | **구현하지 않는다.** §13-C 참조 |

`'object'` 라는 이름은 02의 것이고 이 문서의 `'rebut'` 과 같은 상태다.
**어느 이름을 쓰든 "노직의 판단과 불일치"라는 뜻이지 "틀렸다"가 아니다** (요구사항 §5).

### `ui.js` 호출 지점 — 이게 전부다

| 시점 | 호출 |
|---|---|
| 부팅 (`main.js`) | `NZ.Court.init(document.getElementById('nz-gl'))` → `data-three` |
| 화면 전환 (`NZ.bus` `screen`) | `NZ.Court.setScene(to)` |
| 로비 카드 포커스/호버 · 선택지 포커스 | `NZ.Court.pulse()` |
| 사건 열기 | `NZ.Court.setMood('idle')` |
| **T7** 채점 — 노직의 답과 **일치** | `var ms = NZ.Court.setMood('approve', { seed, streak })` |
| **T7** 채점 — 노직의 답과 **불일치** | `var ms = NZ.Court.setMood('rebut', { seed, streak })` |
| **T9** | `setTimeout(toFeedback, ms)` |
| 완료 사건 재방문 | `NZ.Court.setPose(match ? 'approve' : 'object')` — 애니메이션 없이 정지 포즈 |
| '다음 사건' 클릭 | `NZ.Court.setMood('idle')` — 완료를 기다리지 않는다 |
| 결과 화면 진입 | `NZ.Court.setScene('result')` + `NZ.Court.pulse()` |

> **금지:** `ui.js` 가 `THREE` 를 직접 참조하는 것. three.js가 통째로 없어도 UI는 죽지 않아야 한다.
> **금지:** `Court.ok` 로 분기하는 것. 폴백은 Court가 처리한다.
> **금지:** 애니메이션 길이를 `ui.js` 안의 상수로 복제하는 것. 길이를 아는 쪽은 3D다 — 반환값을 쓴다.
> **금지:** 반환값을 피드백 **표시 시간**으로 쓰는 것. 피드백은 '다음' 버튼을 누를 때까지 남는다(요구사항 §3).
> 반환값은 **반응 → 피드백 사이의 지연**일 뿐이다.

### 비공개 진단 훅 — `ui.js` 는 호출하지 않는다

`SR2/README.md` §6이 적어둔 대로, **브라우저 자동화 탭에서는 `requestAnimationFrame` 이 아예 안 돈다.**
수동 구동기 없이 측정하면 "렌더가 안 돈다"는 유령 결함을 보게 된다(그 저장소에서 네 번 겪었다고 기록돼 있다).

```js
NZ.Court._step(frames, dt);   /* dt 고정으로 n 프레임 진행. 기본 (1, 1/60) */
NZ.Court._probe();            /* -> { calls, tris, programs, mood, t, variant,
                                       quality, dpr, mode, fov, canvasW, canvasH,
                                       paused, ok, reduced } */
```

이름 앞의 `_` 가 계약이다. 공개 API가 아니고, `ui.js` 는 절대 호출하지 않는다.

## 11. 구현 순서와 검증

### 11.1 5단계

| 단계 | 산출물 | 이 단계에서 확인할 것 |
|---|---|---|
| **1. 껍데기** | `init` / `dispose` / `resize` + `ResizeObserver` + 빈 씬 + rAF 루프 + 폴백 경로 | `dispose()` 20회 반복 후 컨텍스트 누수 0. `data-three="off"` 강제 시 배경이 뜨는가. 패널 폭이 변할 때 캔버스가 따라오는가 |
| **2. 세트** | §3.3 정적 세트 merged + 조명 + §2.3 세 카메라 프리셋 | overlay/split/stack 세 모드에서 구도가 §2.4 표와 맞는가. `--nz-band-h: 0px` (높이 559 이하)에서 렌더가 멈추는가. overlay에서 DOM 텍스트 영역 최대 채널값 ≤ `0x3a` |
| **3. 리그** | §4 노직 (포즈는 idle 고정) | §4.4 검증 스니펫 3줄이 전부 허용 오차 안인가. 드로우콜 ≤ 24, 삼각형 ≤ 12,000 |
| **4. 타임라인** | §5 idle / approve / rebut + §5.4 변주 + §6 전이 | `_step(63, 1/60)` 으로 approve를 끝까지 돌려 도장 바닥이 y 1.075±0.015 에 닿는가. rebut `_step(18)` 에서 지휘봉 팁이 1.075±0.015 인가 |
| **5. 폴백과 접근성** | §8 reduced-motion + §9 SVG 폴백 | reduced에서 approve/rebut 구분이 읽히는가. 폴백으로 10개 사건 완주 |

**단계 4를 단계 1~3 앞으로 당기지 마라.** 타임라인 각도는 리그 치수에서 나온 값이라 리그가 확정되기 전에 잡으면 두 번 잡게 된다.

### 11.2 검증 체크리스트

콘솔에서 자동화 가능한 것:

```js
var p = NZ.Court._probe();
p.calls    <= 24                 /* 드로우콜 */
p.tris     <= 12000              /* 삼각형 */
p.programs <= 6                  /* 셰이더 프로그램 */
```

| 항목 | 방법 | 기준 |
|---|---|---|
| 손 위치 | `rig.handR/handL.getWorldPosition()` | §4.4 좌표 ±0.02 |
| 지휘봉 팁 (idle) | `batonMesh.localToWorld(0,0,0.44)` | y 1.10±0.03 |
| 지휘봉 팁 (rebut 임팩트) | `_step` 으로 t=0.30 까지 | y **1.075±0.015** |
| 도장 바닥 (approve 임팩트) | `_step` 으로 t=0.38 까지 | y **1.071±0.015** |
| 지휘봉이 관객 쪽으로 | 전 타임라인에서 팁 월드 z | **≤ 0.55** |
| 밝은 소품의 x | files · lamp · stamp · 손 | **< −0.58** |
| 가로 구도 불변 (overlay) | 캔버스 aspect 1.90 / 1.33에서 노직 좌우 비율 | 7.5% / 33% ±2%p |
| 가로 구도 불변 (split) | 캔버스 aspect 1.02 / 1.24에서 노직 좌우 비율 | 31% / 69% ±2%p |
| 밴드 높이 0 | `@media (max-height:559px)` 강제 | `_probe().paused === true`, 콘솔 경고 0 |
| 반환값 계약 | `setMood('rebut',{streak:3})` · 폴백 상태 · 알 수 없는 mood | 어느 경우에도 `typeof ms === 'number'`, `'idle'` 만 `0` |
| 컨텍스트 누수 | `init`/`dispose` 20회 | 콘솔 경고 0 |
| 전이 튐 | rebut 0.4 s 시점에 `setMood('idle')` | 0.12 s 안에 매끄럽게 |
| 연속 오답 안전장치 | `setMood('rebut', {streak: 3})` | `_probe().variant === 3` |
| 탭 백그라운드 | 탭을 숨겼다 5초 뒤 복귀 | 큰 `dt` 점프 없음, 포즈 정상 |
| reduced-motion | DevTools에서 강제 | 카메라 킥 0, 눈썹 각도 유지 |
| 폴백 완주 | `data-three="off"` 강제 후 | 10개 사건 + 결과 화면 도달 |
| 폴백 + 모션 감소 | 위 상태에서 reduced 강제 | **승인과 반박이 여전히 구분되는가** (§9.5 포즈/장식 분리의 증명) |

사람이 봐야만 아는 것 — **정직하게 남긴다:**

- 노직이 "장난스럽고 엄한 교수"로 읽히는가. 숫자로 확인할 수 없다.
- 반박이 학생에게 **혼나는 느낌**이 아니라 **지적당하는 느낌**으로 오는가. 이건 고2 학생 앞에서 돌려봐야 안다.
- 5분 안에 10개가 끝나는가. 실제 학생에게 재보기 전에는 **"약 5분을 목표로 설계"** 라고만 쓴다(요구사항 §8).

| 5 | 지휘봉으로 사람을 때리거나 카메라 쪽으로 찌르기 | 요구사항 §5. 팁 월드 z ≤ 0.55 |

| 7 | 붉은 화면 플래시 · 반복 번쩍임 | 요구사항 §6. 조명 변화는 1회 +35% 0.30 s가 상한 |

| 10 | 런타임에 라이트 개수 바꾸기 | 전 재질 셰이더 재컴파일. 크롬북에서 수백 ms 스톨 |
| 11 | 품질 단계에서 지오메트리 재생성 | GC 스톨 → 다음 샘플이 나빠짐 → 사다리가 바닥까지 |
| 12 | 컨텍스트 소실 중 성능 샘플링 | 그 프레임은 GPU에 대한 증거가 아니다. 수업 내내 최저 품질에 갇힌다 |
| 13 | 폴백에서 **상태 구분**을 `@keyframes` 에 싣기 | 04 §9.1의 전역 `*{animation-duration:1ms!important}` 가 죽인다. 포즈는 `transition`, 장식만 `animation` (§9.5) |
| 14 | 폴백 클래스를 `animationend` 로 떼기 | 백그라운드 탭에서 안 오고, 모션 감소에서는 1ms 만에 온다. 둘 다 노직을 잘못된 포즈에 굳힌다 |

| 17 | 3D에 점수·진행도·사건 제목 띄우기 | 전부 DOM 소유. 3D가 죽으면 그 정보가 같이 죽는다 |

## 13. 다른 문서와의 충돌 — 중재가 필요한 4건

### A. Court API의 이름과 개수 — **내 과제 지시 vs 02 §7.5**

| | |
|---|---|
| 내 과제 지시 | `init(canvas)→bool`, `setMood(mood, opts)`, `pulse()`, `resize()`, `dispose()`, `ok` — **6개** |
| 02 §7.5 | `init`, `setScene`, `setFiles`, `highlightFile`, `react`, `setPose`, `idle`, `setReducedMotion` — **8개**, `ok` 없음 |

**내 해결:** 핵심 6개를 정본으로 두고, 02의 이름 7개를 **같은 모듈 안 얇은 래퍼**로 얹었다(§10 어댑터 표).
한 구현이 두 문서를 동시에 만족한다. `setFiles`/`highlightFile` 만 빠졌고 그건 C 항목이다.

**중재 필요:** 정본을 어느 쪽으로 할지. 어댑터를 유지하면 `Court` 표면이 13개가 되어 넓다.
02의 이름이 상태 기계와 더 잘 붙으므로, **02를 정본으로 하고 §10의 6개를 내부 함수로 내리는 쪽**도 합리적이다.
어느 쪽이든 §5의 타임라인·§4의 리그는 그대로다.

### B. 모션 감소에서 반응 길이 — **02 §9 vs 이 문서 §8**

| | |
|---|---|
| 02 §9 | 모션 감소 ON → `react()` 가 **`0ms`** 반환. 피드백으로 즉시 전이 |
| 이 문서 §8·§10 | approve **700ms** / rebut **길이 유지**. 진폭만 줄인다 |

**왜 내가 다르게 잡았나.** `0ms` 면 선택하는 순간 판정 카드가 튀어나와 **노직이 반응했다는 사실 자체가 사라진다.**
요구사항 §5는 "기본 대기 / 정답 승인 / 오답 반박 상태가 시각적으로 구분되어야 한다"고 했고,
모션 감소는 그 요구를 면제하지 않는다. §8에서 보인 대로 이 리그는 **진폭이 아니라 눈썹 각도와
소품(도장/지휘봉)** 이 의미를 나르므로, 진폭을 반으로 줄여도 구분이 100% 살아남는다.
줄일 것은 카메라 킥·전진·흔들림이지 **반응의 존재**가 아니다.

**중재 필요:** `0ms` 로 가려면 최소한 **판정 카드에 도장/지휘봉 아이콘이 즉시 보이는 것**이 보장돼야 한다.
04 §9가 "도장 찍힘: 애니메이션 없이 즉시 표시"라고 적어 두었으므로 그 조건은 충족된다.
그래도 나는 **700ms 유지**를 권한다 — 0ms는 "빠른 게 배려"라는 흔한 오해이고,
모션 감소 사용자가 원하는 것은 *움직임이 없는 것*이지 *반응이 없는 것*이 아니다.

### C. 로비의 3D 사건 파일 앵커 — **02 §7.5 vs 이 문서 §1.3·§3.3**

| | |
|---|---|
| 02 §7.5 | `setFiles(list)` · `highlightFile(id)` · `nz:anchors` CustomEvent로 3D 파일 10개의 화면 좌표를 넘기고, ui.js가 그 위에 투명 버튼을 얹는다 |
| 이 문서 | 3D의 파일 더미는 **소품 4장**이다. 로비의 10장은 DOM 카드가 전부 담당한다 |

**비용:** 파일 10개를 개별 오브젝트로 만들면 드로우콜이 16 → 26 (상한 24 초과)이고,
`InstancedMesh` 로 묶어도 상태별 색 변경 + 매 프레임 `project()` 10회 + 리사이즈마다 앵커 재계산이 붙는다.
게다가 내 과제 브리프는 *"3D는 배경과 캐릭터 연출만 담당한다"* 로 시작한다.

**중재 필요.** 세 가지 선택지:

1. **DOM 그리드로 간다** (내 권고). 3D 파일 더미는 소품. 04 §1이 이미 `#nz-file-list` 를
   `repeat(var(--nz-file-cols), …)` 그리드로 정의해 두었고, `data-three="off"` 에서도 같은 그리드가 돌아간다.
   **한 벌의 로비만 만들면 된다.** 키보드·포커스·스크린리더가 전부 공짜로 따라온다.
2. **3D 앵커를 만든다.** 파일 10장을 `InstancedMesh` 1개로, 상태는 인스턴스 색으로.
   드로우콜 +1로 막을 수 있지만 앵커 이벤트와 투명 버튼 정렬 코드가 새로 필요하고,
   `data-three="off"` 용 DOM 그리드도 **어차피 만들어야 한다**(두 벌 유지).
3. 절충: 3D는 파일 더미를 **한 덩어리**로 두고, `highlightFile` 은 그 더미 전체를 살짝 들썩이는 것으로만 응답.
   앵커는 만들지 않는다. DOM 그리드가 로비의 유일한 조작면.

### D. 폴백 노직 요소 — **04 §12 vs 요구사항 §5**

| | |
|---|---|
| 04 §12 | *"새 요소를 추가하지 않고 `#nz-root::before` 가 `#nz-gl` 과 같은 사각형을 덮는다"* |
| 요구사항 §5 | 대기 / 승인 / 반박 세 상태가 **시각적으로 구분**되어야 한다 |

`::before` 하나로는 관절 4개(머리·눈썹·지휘봉·도장)를 따로 움직일 수 없다.
**내 제안: 요소 하나** — `<svg id="nz-fb-bust" hidden>`, `#nz-gl` 의 형제, **court3d.js 소유**,
`#nz-gl` 과 같은 사각형 안(§9.4). 04가 지키려던 것("열 비율·패널·키맵·세로 예산 불변")은 그대로 성립한다.

**중재 필요:** 04가 이 한 개를 허용하는지. 불허라면 대안은
`#nz-root::before` + `::after` 두 개의 의사요소에 `background` 레이어로 눈썹·지휘봉을 그리고
`transform` 으로 움직이는 것인데, 관절 2개가 한계라 **승인/반박 구분은 되지만 표정은 죽는다.**

### 충돌이 아닌데 기록해 둘 것

- 02 §5는 완료 사건 재방문 시 *"노직 반응을 재생하지 않는다 — 정지 포즈만"* 이라고 했다. 옳다.
  `setPose('object')` 는 §5.4의 **v3(조용한 변주)** 끝 포즈로 간다 — 재방문마다 타격음이 반복되면 안 되기 때문이다.
- 02 §7.5의 *"three.js 레이캐스트로 클릭을 받으면 키보드 선택과 어긋난다"* 는 이 문서 §2.6과 같은 결론이다.
- 04 §9.1의 전역 `*{animation-duration:1ms!important}` 는 **내 SVG 폴백 keyframe을 전부 죽인다.**
  충돌이 아니라 **내가 맞춰야 할 제약**이라 §9.5에서 포즈(transition)와 장식(animation)을 분리했다.
  이 분리를 되돌리면 모션 감소에서 승인과 반박이 똑같아진다.
