## 0. 전제 — 크롬북의 실효 뷰포트는 768px이 아니다

주요 검증 크기는 **1366×768**이지만, 그 768px 중 화면이 실제로 받는 높이는 그보다 훨씬 작다.

| 항목 | 높이 |
|---|---|
| 물리 화면 | 768px |
| ChromeOS 셸프(하단 작업표시줄, 기본 자동숨김 꺼짐) | −48px |
| Chrome 탭 스트립 | −40px |
| Chrome 주소창 툴바 | −44px |
| **실효 `window.innerHeight` (창 모드)** | **≈ 636px** |
| F11 전체화면일 때 | 768px |

**설계 바닥값은 636px이다.** 1366×768을 "768px 세로가 있다"고 가정하고 만든 레이아웃은
교실에서 선택지 버튼 아래가 잘린다. 이 문서의 모든 세로 예산은 636px 기준으로 계산되어 있고,
768px(전체화면)은 여유가 남는 경우로만 다룬다.

같은 계산으로:

| 표기 크기 | 실효 뷰포트(창 모드) | 비고 |
|---|---|---|
| 1366×768 | **1366×636** | 주요 검증 크기 |
| 1280×720 | **1280×588** | 세로가 가장 빡빡한 구간 |
| 1024×768 | **1024×636** | 구형 크롬북 / 분할 창 |
| 768×(가변) | 768×≥560 가정 | 태블릿·세로분할 |
| 400×(가변) | 400×≥620 가정 | 휴대폰 |

> 구현 시 첫 작업: 교실 PC에서 `window.innerWidth + "x" + window.innerHeight`를 한 번 찍어
> 636이 맞는지 확인한다. 위 값은 계산값이며, 북마크바가 켜져 있으면 여기서 30px이 더 빠진다.
> 그래서 `@media (max-height: 620px)` 압축 스케일을 아래 §3에 별도로 정의해 둔다.

## 1. 화면 골격 — 세 가지 레이아웃 모드

**DOM 골격과 id는 `02-화면흐름-상태기계.md` §7.2가 소유한다. 이 문서는 요소를 하나도 추가하지 않는다.**
레이아웃은 전부 CSS로만 만든다 — 래퍼 `<div>`를 새로 넣지 않았다.
그래서 02의 골격을 글자 하나 바꾸지 않고도 아래 세 모드가 성립한다.

```
<canvas id="nz-gl" aria-hidden="true" tabindex="-1">        ← #nz-root 의 형제. position:fixed
<div id="nz-root" data-screen data-three data-motion data-sound>   ← position:fixed; inset:0
  <p id="nz-live">  role=status  aria-live=polite           ← 시각적 숨김
  <p id="nz-alert"> role=alert   aria-live=assertive        ← 시각적 숨김
  <header id="nz-hud">                                      ← position:absolute; top:0; 전폭
  <section id="nz-start"  class="nz-screen">                ← 안에 #nz-resume 패널
  <section id="nz-lobby"  class="nz-screen">
  <section id="nz-case"   class="nz-screen" data-phase data-review>
  <section id="nz-result" class="nz-screen">
  <div id="nz-confirm" role="dialog" aria-modal="true">
```

`.nz-screen`은 전부 `position:absolute`이고, 기본 사각형은 HUD 아래 전체다.

```css
#nz-root{ position:fixed; inset:0; overflow:hidden; }
.nz-screen{ position:absolute; top:var(--nz-hud-h); left:0; right:0; bottom:0; }
```

모드 전환은 **`#nz-root[data-screen]`** 하나로 한다(02가 이미 쓰는 속성이다).
레이아웃 전용 클래스를 따로 만들지 않는다.

| 모드 | 조건 | 적용 화면 | 캔버스 | 화면 섹션 |
|---|---|---|---|---|
| **분할** | `[data-screen="case"]` + 폭 ≥ 1024 | `#nz-case` | 좌측 열만 차지 | 우측 열, **완전 불투명** |
| **스택** | `[data-screen="case"]` + 폭 < 1024 | `#nz-case` | 상단 밴드만 차지 | 밴드 아래 전부 |
| **오버레이** | `start` · `lobby` · `result` | 나머지 3개 | 전폭 | 캔버스 위 + 스크림 |

```css
/* 캔버스 — 분할 모드에서 패널 뒤를 렌더하지 않는다 */
#nz-gl{ position:fixed; top:var(--nz-hud-h); left:0; right:0; bottom:0; z-index:var(--nz-z-canvas); }
#nz-gl[data-split="1"]{ right:var(--nz-panel-w); }

/* 패널 — 우측 열 */
#nz-root[data-screen="case"] #nz-case{
  left:auto; width:var(--nz-panel-w);
  background:var(--nz-navy-1);
  border-left:1px solid var(--nz-hair);
}
@media (max-width:1023px){                    /* 스택 */
  #nz-gl[data-split="1"]{ right:0; bottom:auto; height:var(--nz-band-h); }
  #nz-root[data-screen="case"] #nz-case{
    left:0; width:auto; top:calc(var(--nz-hud-h) + var(--nz-band-h));
  }
}
```

`#nz-gl`은 court3d.js 전용이라는 02 §7.1의 모듈 분리를 지키기 위해,
ui.js가 캔버스에서 건드리는 것은 **`data-split` 속성 하나뿐**이다(CSS 스위치 용도).
캔버스의 픽셀 크기는 court3d.js가 `ResizeObserver(#nz-gl)`로 스스로 잡는다.

**분할 모드에서 캔버스는 `inset:0`이 아니다.** 1366 기준 렌더 픽셀이 46% 줄어
크롬북 GPU 부담이 그만큼 줄고, 불투명 패널 뒤를 그리는 낭비가 0이 된다.
DPR 상한: 분할 모드 `Math.min(devicePixelRatio, 1.5)`, 오버레이 모드 `Math.min(devicePixelRatio, 1.25)`.

### 1.1 z-index 스케일 (토큰으로만 사용, 매직넘버 금지)

| 토큰 | 값 | 대상 |
|---|---|---|
| `--nz-z-canvas` | 0 | `#nz-gl` |
| `--nz-z-scrim` | 5 | 오버레이 모드 딤 레이어 (`#nz-root::before`) |
| `--nz-z-panel` | 10 | `.nz-screen` |
| `--nz-z-bubble` | 20 | `#nz-fb-line` (말풍선) |
| `--nz-z-hud` | 30 | `#nz-hud` |
| `--nz-z-dialog` | 60 | `#nz-confirm` + 배경 차단막 |

### 1.2 패널 내부 그리드 — 02의 DOM 순서를 그대로 쓴다

02 §7.2의 `#nz-case` 자식 순서는
`#nz-case-no → #nz-case-title → #nz-case-body → #nz-case-hook → #nz-choices → #nz-feedback`이다.
**이 순서를 바꾸지 않는다.** `order`도, `display:contents`도 쓰지 않는다 —
순서를 바꿔봐야 총 높이는 1px도 줄지 않고, 시각 순서와 DOM 순서만 어긋난다.

```css
#nz-case{ display:grid; align-content:start; row-gap:0; }
#nz-case > *{ min-width:0; }
#nz-case-body{ min-height:0; overflow-y:auto; }      /* 유일한 1fr 행 */
```

`row-gap:0`이고 **각 아이템이 자기 `margin-top`을 가진다.** 이렇게 해야
판정 카드를 이루는 `#nz-feedback` 내부 요소들을 간격 0으로 붙여 한 장으로 보이게 하면서,
바깥 요소 사이 간격만 `--nz-gap-row`로 벌릴 수 있다.

| 요소 | 행 | 위상 `ask` | 위상 `lock` | 위상 `feedback` |
|---|---|---|---|---|
| `#nz-case-no` | auto | 보임 | 보임 | 보임 |
| `#nz-case-title` | auto | 보임 | 보임 | 보임 |
| `#nz-case-body` | **`minmax(0,1fr)`** | 보임 | 보임 | 보임 |
| `#nz-case-hook` | auto | 보임 | 보임 | **`hidden`** |
| `#nz-choices` | auto | 조작 가능 | `disabled` | `disabled` + 배지 |
| `#nz-feedback` | auto | `hidden` | `hidden` | 보임 |
| `#nz-fb-line` | — | — | — | **그리드에서 빠짐** — `position:absolute` 말풍선(§3.5) |

**피드백 위상에서 `#nz-case-hook`을 숨기는 것이 이 레이아웃의 유일한 트레이드오프다.**
숨기지 않으면 1366×636에서 **67px이 넘친다**(훅 블록 72 + margin 12 = 84를 더해야 하는데
여유가 17px뿐이다). 훅 대사는 이미 제 역할(사건을 자극적으로 만드는 것)을 끝냈고,
그 자리는 노직의 반박이 이어받는 편이 대화로 읽힌다.
본문 `#nz-case-body`는 **어떤 위상에서도 사라지지 않는다** — 02 §1의 요구를 지킨다.

`#nz-feedback` 내부는 2열 그리드다. 판정 라벨과 영어 개념어가 같은 행에 앉는다.

```css
#nz-feedback{ display:grid; grid-template-columns:1fr auto; column-gap:12px;
              background:var(--nz-navy-2); border-left:6px solid var(--nz-fb-accent);
              border-radius:0 12px 12px 0; }
#nz-fb-verdict { grid-column:1; }   /* 판정 라벨 + 글리프 */
#nz-fb-en      { grid-column:2; }   /* 영어 개념어, 같은 행 우측 */
#nz-fb-expected,#nz-fb-reason,#nz-fb-nav{ grid-column:1 / -1; }
#nz-fb-line{ position:absolute; }   /* 카드 밖으로 나가 캔버스 열의 말풍선이 된다 */
```

`--nz-fb-accent`는 `#nz-fb-verdict[data-verdict]`에 따라 ui.js가
`--nz-match` / `--nz-miss`로 바꿔 넣는 유일한 인라인 커스텀 프로퍼티다.

## 2. 반응형 구간 — 캔버스 / 패널 비율 확정

분할 기준은 **폭 1024px**. 이상은 좌우 분할, 미만은 세로 스택.

패널 폭은 한 줄 공식으로 고정한다(구간 경계에서 폭이 튀지 않는다):

```css
--nz-panel-w: clamp(492px, 46vw, 640px);
```

### 2.1 분할 모드 (폭 ≥ 1024px)

| 뷰포트 폭 | 패널 폭 | 캔버스 열 폭 | 캔버스 : 패널 | 패널 좌우 패딩 | 본문 줄당 한글 글자 |
|---|---|---|---|---|---|
| 1600 | 640px | 960px | **60.0 : 40.0** | 26px | 33자 (max-width 33em이 먼저 걸림) |
| 1440 | 640px | 800px | **55.6 : 44.4** | 26px | 33자 |
| **1366** | **628px** | **738px** | **54.0 : 46.0** | **26px** | **33자** |
| **1280** | **589px** | **691px** | **54.0 : 46.0** | 24px | 31자 |
| 1152 | 530px | 622px | **54.0 : 46.0** | 24px | 28자 |
| **1024** | **492px** | **532px** | **52.0 : 48.0** | 20px | 26자 |

- 캔버스 열 폭 = `100vw − var(--nz-panel-w)`. 소수점은 `round()` 없이 브라우저에 맡긴다.
- 패널은 배경 `#101A2E` **불투명**. 반투명 패널 금지 — 3D 조명이 움직이면 대비가 흔들린다.
- 패널 좌측에 `1px solid #2E3E5C` 경계선 1줄. 그림자 없음(크롬북에서 비용만 든다).
- 1024px에서 본문 26자/줄이 최저 보장선이다. `--nz-panel-w`의 하한 492px이 이 숫자를 지킨다.

### 2.2 세로 스택 모드 (폭 < 1024px)

`#nz-gl`이 상단 밴드로 줄고, `#nz-case`가 그 아래 전부를 차지한다(§1의 `@media (max-width:1023px)` 블록).

| 뷰포트 | 캔버스 밴드 높이 | 패널 높이 | 캔버스 : 패널 (세로) | 패널 좌우 패딩 |
|---|---|---|---|---|
| 768 × 900 | 240px (= `min(28vh, 240px)`) | 나머지 616px | **28.0 : 72.0** | 20px |
| 768 × 636 | 178px (= 28vh) | 414px | **30.0 : 70.0** | 20px |
| 600 × 800 | 176px | 580px | **23.3 : 76.7** | 16px |
| **400 × 740** | **148px** (= `min(22vh, 180px)`) | **548px** | **21.3 : 78.7** | **14px** |
| 임의 × **< 560** | **0px (`display:none`)** | 전부 | **0 : 100** | 동일 |

- 캔버스 밴드 공식: 폭 ≥ 600px → `height: min(28vh, 240px)` / 폭 < 600px → `height: min(22vh, 180px)`.
- **세로 560px 미만이면 캔버스 밴드를 통째로 숨긴다.** 3D보다 읽기가 먼저다.
  이때 노직의 반응은 패널 안의 판정 카드 텍스트로만 전달되며, 게임은 그대로 완주된다.
- 스택 모드에서는 **패널 전체 세로 스크롤을 허용**한다(§3.4). 단 잘림은 여전히 0이다.

### 2.3 스크롤 정책

| 영역 | 정책 |
|---|---|
| `html, body` | `overflow: hidden` — 페이지 전체 스크롤은 어떤 폭에서도 0 |
| 가로 스크롤 | 전 구간 **0**. `#nz-case`와 모든 그리드 아이템에 `min-width: 0` 필수 |
| `#nz-case-body` (상황 본문) | 분할 모드에서 유일하게 스크롤 가능한 블록. 넘칠 때만 `overflow-y:auto` |
| `.nz-screen` | 폭 < 1024px에서만 `overflow-y: auto`, `overscroll-behavior: contain` |
| 로비 그리드 | 폭 ≥ 1024px에서 스크롤 **0** (§6에서 예산으로 보장). 미만은 스크롤 허용 |

`#nz-case-body`가 실제로 넘칠 때만 JS가 `tabindex="0"` + `role="group"` +
`aria-label="사건 상황"`을 붙인다(키보드로 스크롤 가능하게). 넘치지 않으면 붙이지 않는다 —
불필요한 탭 스톱을 만들지 않기 위해서다.

## 3. 세로 예산 — 스크롤 없이 들어간다는 증명

아래 표는 **1px 단위로 합이 맞는 실제 계산**이다. 값을 바꾸려면 표를 다시 맞춰야 한다.
`#nz-case-body`만 `minmax(0,1fr)`이고 나머지는 전부 `auto`라,
**선택지와 다음 버튼은 어떤 높이에서도 잘리지 않는다.** 모자라면 본문만 줄어들고 스크롤이 생긴다.

### 3.1 기본 스케일 · 위상 `ask` · 1366×636

| 요소 | 계산 | 높이 |
|---|---|---|
| `#nz-hud` | 고정 | 48 |
| `#nz-case` 상단 패딩 | | 20 |
| `#nz-case-no` | 13px × 1.3 | 17 |
| `margin-top` | | 6 |
| `#nz-case-title` | 22px × 1.32, **1줄** (§13.1 제목 24자 상한) | 29 |
| `margin-top` | | 14 |
| **`#nz-case-body`** | 17px × 1.72 = 29.2 → **4줄** | **116** |
| `margin-top` | | 14 |
| `#nz-case-hook` | 16px × 1.5 × 2줄 = 48 + 패딩 12×2 | 72 |
| `margin-top` | | 14 |
| `#nz-choice-1` | 17px × 1.5 × 2줄 = 51 + 패딩 16×2 + 테두리 2 | 85 |
| `margin-top` | | 10 |
| `#nz-choice-2` | 동일 | 85 |
| `#nz-case` 하단 패딩 | | 16 |
| **합계** | | **546** |
| **636 대비 여유** | | **+90** |

`ask` 위상에는 하단 버튼이 없다. `#nz-btn-lobby`는 HUD에 있고(§13.2 협의 1),
키 힌트는 `.nz-choice-key`가 `A` 아래 작은 `1` 키캡을 함께 그려 대신한다 —
**새 요소를 만들지 않는다.** 남는 90px은 `#nz-case-body`의 `1fr` 행이 흡수해
본문이 상단에 붙은 채 아래가 비는 형태가 된다(`align-content:start`).

### 3.2 기본 스케일 · 위상 `feedback` · 1366×636

`#nz-case-hook`이 `hidden`이 되고, 그 자리를 **선택지 아래의 판정 카드**가 받는다.
선택지는 남되 내부 패딩이 16 → 10으로 줄고(`[data-phase="feedback"]`), 외곽 `margin-top`은 14 → 12.

| 요소 | 계산 | 높이 |
|---|---|---|
| `#nz-hud` | | 48 |
| 상단 패딩 | | 20 |
| `#nz-case-no` | | 17 |
| `margin-top` | | 6 |
| `#nz-case-title` | | 29 |
| `margin-top` | | 12 |
| **`#nz-case-body`** | **4줄 유지** | **116** |
| `margin-top` | | 12 |
| `#nz-choice-1` | 51 + 패딩 10×2 + 테두리 2 | 69 |
| `margin-top` | | 10 |
| `#nz-choice-2` | 동일 | 69 |
| `margin-top` | | 12 |
| `#nz-fb-verdict` + `#nz-fb-en` (한 행) | 14px × 1.3 = 19 + 패딩 13/6 | 38 |
| `#nz-fb-expected` | 15px × 1.55 = 23 + 패딩 0/6 | 29 |
| `#nz-fb-reason` | 15px × 1.55 × 2줄 = 47 + 패딩 0/13 | 60 |
| `margin-top` | | 12 |
| `#nz-fb-nav` (`#nz-btn-next`) | 높이 고정 | 44 |
| 하단 패딩 | | 16 |
| **합계** | | **619** |

판정 카드 3행(38 + 29 + 60 = **127**)은 서로 `margin-top:0`이라 한 장으로 붙는다.

## 4. 타이포그래피

### 4.1 폰트 스택 — 한국어는 웹폰트를 쓰지 않는다

**결정: 한국어 본문에 웹폰트를 로드하지 않는다.**
근거 (1) 한국어 웹폰트는 서브셋해도 수백 KB이고, 학교 와이파이에서 첫 문단이 늦게 뜬다.
(2) 이 자료는 오프라인 더블클릭으로도 굴러가야 한다.
(3) 크롬북에는 Noto Sans CJK KR이 기본 탑재되어 있어 시스템 스택만으로 품질이 확보된다.

웹폰트는 **라틴 전용 2종만** `<link>`로 가져오고, 실패해도 텍스트는 즉시 대체 폰트로 그려진다.

```css
--nz-f-ko:  "Pretendard", "Noto Sans KR", "Apple SD Gothic Neo",
            "Malgun Gothic", "맑은 고딕", system-ui, -apple-system, sans-serif;
--nz-f-en:  "Spectral", "Iowan Old Style", Georgia, "Times New Roman", serif;
--nz-f-num: "Barlow Condensed", "Oswald", "Arial Narrow",
            system-ui, -apple-system, "Segoe UI", sans-serif;
```

- `<head>`에 `<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>` 1개와
  `<link rel="stylesheet" href="…css2?family=Barlow+Condensed:wght@500;700&family=Spectral:ital,wght@0,400;0,600&display=swap">` 1개. **그 외 외부 요청 0건.**
- `display=swap` 고정. 폰트 로딩을 기다리는 JS(`document.fonts.ready` 대기 후 렌더 등)를 **쓰지 않는다.**
- `--nz-f-en`이 실패하면 Georgia로 떨어진다. 영어 개념어는 한 줄짜리 짧은 문구뿐이라
  줄바꿈이 달라져도 레이아웃이 깨지지 않는다.
- `--nz-f-num`이 실패하면 system-ui로 떨어진다. HUD 숫자는 폭이 흔들리면 안 되므로
  **`font-variant-numeric: tabular-nums`를 반드시 함께 건다**(대체 폰트에서도 작동).
- 한국어 대체 폰트가 Windows(Malgun Gothic)와 ChromeOS(Noto Sans CJK KR)에서 다르므로
  **`line-height`에 `normal`을 쓰지 않는다.** 전 항목 숫자 배수로 명시(아래 표).

### 4.3 한국어 줄바꿈 — 잘림 0을 만드는 규칙

전역으로 한 번만 선언한다.

```css
.nz-ko{
  word-break: keep-all;        /* 어절 중간에서 끊지 않는다 */
  overflow-wrap: anywhere;     /* 단, 한 어절이 줄보다 길면 그때만 끊는다 */
  line-break: strict;
  hyphens: none;
}
#nz-case-title{ text-wrap: balance; }   /* Chrome 117+. 미지원 시 무시되어도 안전 */
#nz-case-body,.nz-choice-text{ text-wrap: pretty; }
```

- `keep-all` 단독은 `300만 원짜리`처럼 긴 어절에서 가로 오버플로를 만든다.
  `overflow-wrap: anywhere`를 **반드시 짝으로** 건다. `break-word`가 아니라 `anywhere`다.
- 숫자+단위는 어절을 붙여 쓴다: `100억`(O) / `100 억`(X). 데이터 파일 작성 규칙이다.
- 끊기면 안 되는 구는 U+2060(WORD JOINER)이 아니라 `<span class="nz-nb">`(`white-space:nowrap`)로 감싼다.
  대상은 `A/B` 배지, `3/10` 같은 진행 표기, `justice in initial holdings` 같은 영어 개념어.

### 4.4 금지 사항 — 글자 잘림 방지

| 금지 | 이유 |
|---|---|
| `text-overflow: ellipsis` | 문서 전체에서 **사용 금지**. 사건 제목·선택지에서 조건이 통째로 사라진다 |
| `-webkit-line-clamp` | **사용 금지**. 로비 카드 제목도 클램프하지 않고 행 높이로 맞춘다(§6.2) |
| `white-space: nowrap` (본문류) | 배지·숫자 표기 외 금지 |
| 고정 `height`가 걸린 텍스트 컨테이너 | `min-height`만 사용 |
| `overflow: hidden`이 걸린 텍스트 블록 | §2.3에 명시된 스크롤 컨테이너 외 금지 |

### 4.5 판정 조건 강조

정당한 소유 / 자발성 / 사기 여부처럼 판정을 좌우하는 구는 다음 하나로만 표시한다.

마크업은 02 §7.2가 확정한 `<mark class="nz-key" data-key="…">`를 그대로 쓴다.
`<mark>`의 브라우저 기본 배경(노란색)을 반드시 리셋해야 한다 — 안 하면 남색 위에 형광 노랑이 뜬다.

```css
mark{ background:none; color:inherit; }     /* 기본 스타일 제거. 이 한 줄이 없으면 화면이 망가진다 */
.nz-key{
  color: var(--nz-amber-2);          /* #FFD98A — 12.85:1 */
  font-weight: 600;
  text-decoration: underline;
  text-decoration-thickness: 2px;
  text-underline-offset: 4px;
  text-decoration-color: rgba(255,217,138,.62);
}
```

- 배경 칠(`background`)을 쓰지 않는다. 짙은 남색 위 앰버 16% 블렌드는 `#363533`이라는
  탁한 올리브가 되고, 줄바꿈 시 배경이 어긋나 보인다.
- 색 + 굵기 + 밑줄 **3중 부호화**다. 색각 이상에서도 굵기·밑줄이 남는다.
- **사건 하나당 최대 2곳.** 3곳 이상이면 강조가 강조를 지운다.
- `data-key`(`holding` / `voluntary` / `fraud` 등)는 **스타일을 바꾸지 않는다.** 세 조건에
  서로 다른 색을 주면 학생이 색을 외우려 들고, 그 순간 이중 부호화가 색 부호화로 퇴화한다.
  `data-key`는 테스트와 콘텐츠 검수용 표식일 뿐이다.
- 끊기면 안 되는 구는 `<mark class="nz-key nz-nb">`로 `nz-nb`를 함께 준다.
- ChromeVox는 `<mark>`를 기본으로 낭독하지 않는다. 보조 텍스트를 넣지 않는 이유가 여기 있다.
- 이 강조에 `aria-label`이나 보이지 않는 "중요" 텍스트를 붙이지 않는다 —
  한 화면에서 두 번 반복되면 낭독이 시끄러워진다.

> 학생이 자기 판정을 보는 경로는 이미 있다 — 카드를 열면 이전 선택과 해설·판정이 그대로 보인다.
| 로비: 현재 | `.nz-file[data-current="true"]` | `#FFC24D` | `▶` | `지금 여기` | 테두리 **2px**, 좌측 6px 실선 바 |
| 진행도 도트 | `.nz-dot[data-state]` | 색 안 씀 | 빈 원 / 꽉 찬 원 / 가로 알약 | 옆에 `완료 3 / 10` | — |

`data-state`와 `data-current`는 서로 독립이다. 현재 사건이 미열람이면 두 표시가 겹치는데,
그때는 `data-current`가 이긴다(테두리 2px 앰버 + `▶`). `data-current="true"`인 완료 사건은
발생하지 않는다 — "현재"는 미응답 사건 중 최소 번호이기 때문이다(§6.4).

**`≠`(U+2260)를 쓴 이유.** `✗`는 "오답"으로 읽히고, 이 활동에서 학생의 선택은
틀린 답이 아니라 "노직과 다른 답"이다. `≠`는 그 뜻을 글리프 자체로 말한다.
`✓`와 획 구성이 완전히 달라 흑백으로 인쇄해도 구분된다.

**요구사항 §5의 "정답/오답은 노직의 판단과 일치/불일치라는 뜻이 드러나야 한다"를
UI 문자열 수준에서 못 박는다.** 화면 어디에도 "정답 / 오답 / 맞았습니다 / 틀렸습니다"를
쓰지 않는다. 허용 문자열은 다음 4개뿐이다.

| 자리 | 문자열 |
|---|---|
| 판정 라벨(일치) | `노직의 판단과 일치` — 02의 `.nz-fb-word` |
| 판정 라벨(불일치) | `노직의 판단과 다름` |
| 선택지 배지 | `노직의 답` / `내 선택` |
| 예상 답 줄 | `노직의 예상 답: B` — 02의 `#nz-fb-expected` |
| 결과 화면 | `노직 예측 정확도: X/10` — 02의 `#nz-result-score` |
| 로비 배지 | `미열람` / `완료 · 일치` / `완료 · 다름` / `지금 여기` |

```css
#nz-file-list{
  display:grid;
  gap:16px;
  margin:0; padding:0; list-style:none;      /* <ul role="list"> 기본 스타일 제거 */
  grid-template-columns:repeat(var(--nz-file-cols),minmax(0,1fr));

.nz-file{ width:100%; height:100%; }          /* <button> 이 칸을 꽉 채운다 */
```

`<li>`에 `display:contents`를 주는 이유: 02의 마크업은 `<ul> > <li> > <button>` 구조인데,
`<li>`가 그리드 아이템이 되면 카드 높이 균등화가 `<button>`까지 전달되지 않는다.
`display:contents`로 `<li>`를 투명하게 만들면 `<button>`이 직접 그리드 아이템이 된다.
`role="list"`가 `<ul>`에 명시돼 있으므로 목록 시맨틱은 유지된다.

**제목을 클램프하지 않는다.** 가장 긴 제목(`월급 250만 원, 억만장자에게 300만 원 선물`,
한글 환산 약 20.4em)이 158px 카드에서 15px 폰트로 3줄이 된다. 카드 높이 150px은
3줄 제목(60px)을 담고도 배지·상태 라벨이 들어가는 값이다. 4줄이 나오는 제목이
생기면 `grid-auto-rows`가 그 행만 키우고, 같은 행의 카드는 `1fr`로 같이 커진다.

### 6.3 제목만 봐도 궁금해지는 카드

카드에 상황 요약을 넣지 않는다. **번호 + 제목 + 상태**뿐이다.
요구사항의 10개 제목은 이미 숫자와 모순을 품고 있어(`춤 10초에 3억`,
`찬성률 99%, 부자 한 명 재산 나눠 갖자`) 설명을 덧붙이면 오히려 김이 샌다.

- 제목 안의 **숫자만** `--nz-f-num` + `--nz-amber`로 칠한다(`100억`, `99%`, `10초`).
  카드 10장이 숫자 열로 먼저 읽히고, 그게 "뭐지?"를 만든다.
  구현: 정규식으로 자동 감싸지 않는다(`10초`의 `10`만 잡고 `억`은 못 잡는다).
  콘텐츠 데이터에 `titleHTML` 필드를 두고 `<i>100억</i>` 형태로 직접 넣는다.
  → 콘텐츠 문서와의 협의 사항(§13.2 협의 2). 이 필드를 두지 않기로 하면 제목을 단색으로
  처리하고 이 항목만 삭제한다 — 레이아웃 예산에는 영향이 없다.
- hover/focus: 카드가 `translateY(-3px)` + 테두리 `--nz-amber`. 모션 감소 시 이동 없이 테두리만.
- 카드 전체가 `<button class="nz-file">`이다. 내부에 중첩 버튼·링크 없음.
- 02의 `.nz-file-no`(`01`)는 `--nz-f-num` 16px, `--nz-ink-3`. 제목보다 먼저 읽히면 안 되므로
  앰버를 쓰지 않는다. 숫자 강조는 **제목 안에서만** 한다.

**"현재"의 정의**: 아직 답하지 않은 사건 중 가장 낮은 번호. 항상 정확히 1개다.
10개 전부 완료되면 `data-current="true"`가 어디에도 붙지 않고, 대신 `#nz-lobby-hint` 자리가
`결과 보기 →` 버튼으로 바뀐다(높이 44px, 예산 20 → 44이므로 여유 +72 → +48).

**접근 이름은 `aria-label`로 통째로 준다.** 02의 `aria-describedby="nz-file-state-…"`는
**쓰지 않는다** — 배지 텍스트가 버튼 내용에도 있고 `describedby`로도 참조되어 두 번 낭독된다.
대신 `.nz-file-no`와 `.nz-file-badge`에 `aria-hidden="true"`를 주고,
버튼에 `aria-label="사건 3. 춤 10초에 3억. 미열람."`을 ui.js가 매번 갱신한다. (§13.2 협의 3)

**도장 마크**: 32px 원, 테두리 `2px solid`(일치=실선 `#5BD7B4` / 다름=점선 `#FF9A62`),
안에 `✓` / `≠` 20px, 배경 투명, `transform: rotate(-9deg)`.
회전은 모션이 아니라 정적 스타일이므로 모션 감소 설정에서도 유지한다.

### 6.5 진행도 표시

두 숫자를 **절대 섞지 않는다**(요구사항 §3).

```
완료  3 / 10   ·   노직 예측 일치  2      ← 한 줄. 왼쪽이 진척, 오른쪽이 점수
[▮▮▮░░░░░░░]                              ← progressbar, 10칸 눈금
```

02의 `#nz-hud-progress`(`완료 <b id="nz-hud-done">0</b>/<span id="nz-hud-total">10</span>`)는
**HUD 전용**이고, 로비 화면의 이 블록은 별도다. 두 곳이 같은 상태를 읽어 같은 숫자를 낸다.

| 자리 | 마크업 |
|---|---|
| 막대 | `<div role="progressbar" aria-valuemin="0" aria-valuemax="10" aria-valuenow="3" aria-label="완료한 사건">` |
| 막대 치수 | 폭 `min(420px, 100%)`, 높이 8px, 반경 4px, 바닥 `#14203A`, 채움 `#FFC24D` |
| 눈금 | 10칸 경계에 `1px` `#0A1020` 세로선 9개 (`repeating-linear-gradient`) — 칸 수가 색 없이 보인다 |
| 일치 수 | `<p>` 일반 텍스트. progressbar 아님(진척도가 아니라 점수이므로) |

HUD의 도트 열은 같은 정보의 축약판이다(§7.1).

바닥 `var(--nz-navy-1)`, 하단 `1px solid var(--nz-hair)`.

**`#nz-hud-clock`은 `aria-hidden="true"`로 바꾼다.** 02는 `aria-label="경과 시간"`을 달아 뒀는데,
1초마다 바뀌는 값에 접근 이름이 붙어 있으면 ChromeVox가 커서를 지나갈 때마다 읽는다.
경과 시간은 주변 정보이고, 같은 값이 결과 화면 `#nz-result-time-v`에 낭독 가능한 형태로 다시 나온다.
(§13.2 협의 4)

**도트 10개**는 02 골격에 없는 유일한 시각 요소다 — `#nz-hud-progress` 안에
`<span class="nz-dot" aria-hidden="true" data-state="unread">` 10개를 ui.js가 넣는다.
텍스트 `완료 3/10`이 이미 같은 정보를 낭독하므로 도트는 전부 `aria-hidden`이다.

도트 3상태(**색 없이 모양으로만**): 미열람 = `1.5px` 외곽선 빈 원 / 완료 = 꽉 찬 원 /
현재 = 가로 20×10 알약. 색은 전부 `#93A2BA` 하나로 통일한다.
**도트는 일치/불일치를 표시하지 않는다** — 로비 카드와 정확히 같은 3상태만 표시한다.
일치 수는 HUD에 넣지 않는다(폭이 모자라고, 로비 화면과 결과 화면에 이미 있다).

### 7.2 전 화면 키맵

문자 키는 **`event.code`로 판정한다**(`KeyA`, `KeyB`, `KeyM` …).
한글 IME가 켜져 있어도 `code`는 바뀌지 않는다. `event.key`로 판정하면 한글 입력 상태에서 죽는다.
숫자는 `Digit0~Digit9` + `Numpad0~Numpad9` 둘 다 받는다.

| 화면 | 키 | 동작 |
|---|---|---|
| **전역** | `KeyM` | 효과음 On/Off 토글 (`#nz-btn-mute`에 포커스 이동 없음, `aria-pressed` 갱신 + live 알림) |
| | `KeyF` | 전체화면 토글 (`requestFullscreen` 실패 시 무시, 오류 표시 없음) |
| | `Tab` / `Shift+Tab` | 포커스 순환. 다이얼로그가 열려 있으면 그 안에 갇힌다 |
| | `KeyR` | `lobby`·`case`·`result`에서 `#nz-btn-restart` 실행(확인 모달) |
| **시작** `#nz-start` | `Enter` · `Space` | `#nz-btn-start` 실행 |
| | 그 외 | 무시 |
| **이어하기 패널** `#nz-resume` | `←` `→` | `#nz-btn-resume` ↔ `#nz-btn-fresh` 포커스 이동 |
| | `Enter` · `Space` | 포커스된 버튼 실행 |
| | `Esc` | **무시**(반드시 하나를 골라야 하므로 닫히지 않는다) |
| **로비** `#nz-lobby` | `←` `→` | 좌/우 카드. 행 끝에서 다음/이전 행으로 넘어간다(전체 10칸 순환) |
| | `↑` `↓` | 위/아래 행의 같은 열. 위/아래가 없으면 이동하지 않는다 |
| | `Home` / `End` | 사건 1 / 사건 10 |
| | `Digit1`~`Digit9` | 사건 1~9 **즉시 열기** |
| | `Digit0` | 사건 10 즉시 열기 |
| | `Enter` · `Space` | 포커스된 카드 열기 |
| | `Esc` | 무시(로비가 홈이다) |
| | `Tab` | 그리드 전체가 **탭 스톱 1개**(roving tabindex). 다음 Tab은 HUD로 |
| **사건·`ask`** `#nz-case[data-phase="ask"]` | `Digit1` · `KeyA` | `#nz-choice-1` 확정 |
| | `Digit2` · `KeyB` | `#nz-choice-2` 확정 |
| | `↑` `↓` `←` `→` | 선택지 포커스 이동(2개 순환) |
| | `Enter` · `Space` | 포커스된 선택지 확정 |
| | `Esc` | 로비로. 기록 없음(아직 답하지 않았으므로) |
| **사건·`lock`** | 모든 키 | **전부 무시.** 반응 애니메이션 중 (02 T9) |
| **사건·`feedback`** | `Enter` · `Space` · `→` | `#nz-btn-next` (마지막 사건이면 `결과 보기`) |
| | `Digit1` `Digit2` `KeyA` `KeyB` | **무시**(입력 잠금) |
| | `Esc` | 로비로. 기록 유지 |
| | `←` | 무시(이전 사건으로 되돌아가는 동선은 없다 — 로비로만 나간다) |
| **결과** `#nz-result` | `Esc` | `#nz-btn-result-lobby` (로비로) |
| | `←` `→` | `#nz-btn-agree-yes` ↔ `#nz-btn-agree-no` 포커스 이동 |
| | `Enter` · `Space` | 포커스된 버튼 실행 |
| **다이얼로그** `#nz-confirm` | `Esc` | 취소 후 닫기 |
| | `Tab` | 다이얼로그 내부에 가둠(첫↔마지막 순환) |
| | `Enter` · `Space` | 포커스된 버튼 실행 |

**키 힌트를 어디에 두는가** — 02 골격에 새 요소를 만들지 않는다.

| 화면 | 힌트 | 자리 |
|---|---|---|
| 로비 | `숫자 키 1–9, 0 으로도 열 수 있습니다` | `#nz-lobby-hint` (02에 이미 있다) |
| 사건 | `1` / `2` 키캡 | `.nz-choice-key` 안. `A` 아래 10px 키캡을 함께 그린다 |
| 사건 | `Esc` | `#nz-btn-lobby` 라벨에 포함 — `◀ 사건 목록 (Esc)` |
| 피드백 | `Enter` | `#nz-btn-next` 라벨에 포함 — `다음 사건 → (Enter)` |

키캡 스타일: `--nz-f-num` 10px, `1px solid var(--nz-line)`, 반경 3px, 패딩 `1px 4px`,
색 `var(--nz-ink-3)`. 터치 기기에서도 숨기지 않는다 — 크롬북은 둘 다 쓴다.

### 7.3 연타 방지

요구사항 §3 "답을 고르면 즉시 입력을 잠가 중복 채점을 막는다"를 두 겹으로 구현한다.

| 겹 | 규칙 |
|---|---|
| ① 상태 잠금 | 첫 선택 즉시 `state.locked = true`. 선택지 버튼 `disabled` + `aria-disabled="true"` |
| ② 입력 유예 | 피드백 진입 후 **450ms** 동안 `Enter`/`Space`/클릭으로 인한 "다음" 입력을 무시 |

②가 없으면 `Enter`를 길게 누른 학생이 선택과 동시에 피드백을 건너뛴다.
450ms는 요구사항의 반응 애니메이션 0.6~1.2초보다 짧으므로, 애니메이션을 끝까지
기다리게 만들지는 않는다. 유예 중 `#nz-btn-next`는 `disabled`가 아니라 **시각적으로 그대로**
두고 이벤트만 무시한다(버튼이 깜빡이면 그게 더 산만하다).

### 7.4 포커스 링

```css
:focus{ outline:none; }
:focus-visible{
  outline:3px solid var(--nz-amber);
  outline-offset:2px;
  box-shadow:0 0 0 5px rgba(10,16,32,.92);   /* 어떤 배경 위에서도 3:1 보장 */
  border-radius:inherit;
}
```

- 앰버 링(9.64~11.80:1)에 더해 바깥쪽 어두운 헤일로를 둔다. 말풍선이나 3D 캔버스 위에
  올라간 요소도 배경 밝기와 무관하게 링이 보인다.
- `:focus-visible`만 사용한다. 마우스 클릭에는 링이 뜨지 않는다.
- **어떤 요소에서도 `outline:none`을 단독으로 쓰지 않는다.** 위 전역 규칙이 `:focus-visible`로
  즉시 되살리는 구조이므로, 개별 컴포넌트에서 `outline` 제거를 다시 쓰면 안 된다.
- 포커스 링이 잘리지 않도록, 포커스 가능한 요소를 담은 컨테이너에 `overflow:hidden`을 걸지 않는다.
  스크롤 컨테이너(§2.3)에는 `padding: 0 5px`로 링 여유를 준다.

### 7.5 화면 전이 시 포커스 이동 대상

전이 직후 `requestAnimationFrame` 1회 뒤에 `.focus({preventScroll:true})`를 호출한다.

| 전이 | 포커스 대상 | `tabindex` |
|---|---|---|
| 페이지 로드 → 시작 | `#nz-btn-start` | 기본 |
| 로드 → 이어하기(저장 있음) | `#nz-btn-resume` | 기본 |
| 시작 → 로비 | 현재 사건 카드 `.nz-file[data-current="true"]` | roving `0` |
| 로비 → 사건 | `#nz-case-title` | `-1` |
| 선택 확정 → 피드백 | `#nz-fb-verdict` | `-1` |
| 피드백 → 다음 사건 | `#nz-case-title` | `-1` |
| 피드백 → 결과 | `#nz-result-title` | `-1` (02에 이미 `tabindex="-1"`) |
| 사건 → 로비 (`Esc` 또는 `#nz-btn-lobby`) | 방금 나온 사건의 카드 | roving `0` |
| 결과 → 로비 | 현재 카드가 없으므로 `#nz-lobby-hint` 자리의 `결과 보기` 버튼 | 기본 |
| `#nz-confirm` 열림 | `#nz-btn-confirm-no` (파괴적 동작을 기본 포커스로 두지 않는다) | 기본 |
| `#nz-confirm` 닫힘 | 모달을 연 버튼(`#nz-btn-restart` 등) | 기본 |

제목에 포커스를 주는 이유: 스크린리더가 화면 진입 즉시 **사건 제목부터** 읽기 시작한다.
`#nz-btn-next`로 바로 보내면 본문을 건너뛴 채 "다음 사건 버튼"만 읽는다.

02는 `.nz-screen` 4개에 전부 `tabindex="-1"`을 달아 뒀다. 그 중
**`#nz-case`에는 포커스를 주지 않는다** — 섹션에 포커스하면 ChromeVox가 섹션 전체를
한 번에 읽어 버려 사건 번호·제목·본문·훅·선택지가 끊김 없이 쏟아진다.
`#nz-case-title`(역시 `tabindex="-1"`)에 주면 제목 → 본문 → 선택지 순으로 끊어 읽는다.
`#nz-lobby`·`#nz-result`는 섹션 포커스를 써도 되지만, 위 표대로 구체 요소를 우선한다.

## 8. 스크린리더 최소 대응

전면 대응이 목표가 아니다. **ChromeVox를 켠 학생이 10문제를 끝까지 풀 수 있는 것**이 목표다.

### 8.1 랜드마크

| 요소 | 역할 |
|---|---|
| `#nz-hud` | `<header>` → `role="banner"` (암묵) + `aria-label="진행 상황"` |
| 현재 화면인 `.nz-screen` | `role="main"`을 명시. **화면 전환 시 이전 화면에서 떼고 새 화면에 붙인다** — 페이지에 항상 정확히 1개 |
| `#nz-file-list` | `<ul role="list">` 유지. `<nav>`로 감싸지 않는다 — 02 골격에 래퍼가 없고, 10개 버튼 목록은 목록 시맨틱으로 충분하다 |
| `#nz-gl` · `#nz-fb-line` | `aria-hidden="true"` (3D 캔버스와 말풍선 둘 다) |
| `#nz-live` | `role="status" aria-live="polite" aria-atomic="true"` + `.nz-sr` |
| `#nz-alert` | `role="alert" aria-live="assertive"` + `.nz-sr` — **저장 실패·치명 오류 전용**(§8.2) |
| `#nz-confirm` | `role="dialog" aria-modal="true" aria-labelledby="nz-confirm-title"` (02가 이미 지정) |

`#nz-gl`과 `#nz-fb-line`에 `aria-hidden`을 걸었으므로, 그 안에 포커스 가능한 요소를 두면 안 된다
(숨겨진 요소에 포커스가 가면 ChromeVox가 침묵한다). `#nz-gl`에는 `tabindex="-1"`을 명시한다.

### 8.2 `aria-live` — 무엇을 언제 읽히나

`#nz-live`는 **페이지 로드 시점부터 DOM에 존재**해야 하고, 내용만 갈아끼운다.
live 영역을 뒤늦게 삽입하면 첫 알림이 낭독되지 않는다.

| 시점 | `#nz-live`에 넣는 문자열 |
|---|---|
| 화면 전환 | `사건 선택 화면. 완료 3, 남은 사건 7.` / `결과 화면.` |
| 사건 열림 | (넣지 않음 — `#nz-case-title` 포커스가 제목을 읽는다) |
| **피드백 표시** | `노직의 판단과 일치. 노직의 예상 답은 B, 정당한 재산을 자발적으로 받았다면 가질 권리가 있다. 노직: 바로 그거야. 이유: 수령자의 노력보다 재산의 출처와 자발적인 이전이 핵심이다. 핵심 영어: Voluntary transfer.` |
| 음소거 토글 | `효과음 켬.` / `효과음 끔.` |
| 전체 초기화 완료 | `기록을 지웠습니다. 사건 10건이 모두 미열람 상태입니다.` |

`#nz-alert`(assertive)에 넣는 것은 **딱 하나**다.

| 시점 | `#nz-alert`에 넣는 문자열 |
|---|---|
| 저장 불가 환경 감지 | `이 브라우저에서는 진행 상황이 저장되지 않습니다. 게임은 그대로 진행됩니다.` |

그 외 어떤 것도 assertive로 보내지 않는다 — 낭독 중인 문장을 잘라 먹는다.
특히 **피드백은 절대 `#nz-alert`에 넣지 않는다.**

- 피드백 문자열은 **판정 → 노직의 예상 답 → 노직의 대사 → 이유 → 영어 개념** 순서 고정.
  화면의 시각 순서(판정 카드 → 말풍선 → 선택지 배지)와 다르지만, 낭독에서는
  결론을 먼저 주는 편이 짧은 도입 활동에 맞다.
- 말풍선 텍스트가 여기 포함되므로 `#nz-fb-line`은 `aria-hidden="true"`다. **중복 낭독 금지.**
- 피드백은 `#nz-live`(polite)로만 간다. `#nz-alert`(assertive)는 위 표의 1건 전용이다.
- 같은 문자열을 연속으로 넣으면 낭독되지 않는다. 동일 문자열 재알림이 필요하면
  끝에 U+200B를 토글로 붙인다.

### 8.3 버튼 접근 이름

| 버튼 | 접근 이름 | 방법 |
|---|---|---|
| `#nz-choice-1` | `선택지 A. 노력하지 않았으니 그 돈을 가질 권리가 없다.` | `aria-label`. `.nz-choice-key`(`A`)와 키캡은 `aria-hidden="true"` |
| `#nz-choice-2` | `선택지 B. 정당한 재산을 자발적으로 받았다면 가질 권리가 있다.` | 동일 |
| `[data-expected="true"]` | 위 + ` 노직의 답.` | `aria-label` 갱신 |
| `[data-picked="true"]` | 위 + ` 내 선택.` | `aria-label` 갱신 |
| `.nz-file` | `사건 3. 춤 10초에 3억. 미열람.` | `aria-label`. `.nz-file-no`·`.nz-file-badge`는 `aria-hidden="true"` |
| `#nz-btn-lobby` | `사건 목록 (Esc)` | 텍스트 |
| `#nz-btn-next` | `다음 사건 (Enter)` / `결과 보기 (Enter)` | 텍스트 + `data-action` |
| `#nz-btn-mute` | `효과음` + `aria-pressed`(소리 상태) | `aria-label="효과음"` + 보이는 텍스트 `소리 끔`/`소리 켬` (§13.2 협의 5) |
| `#nz-btn-start` | `법정 열기` | 텍스트 |
| `#nz-btn-resume` / `#nz-btn-fresh` | `이어하기. 완료 3건이 있습니다.` / `처음부터. 기록을 지웁니다.` | `aria-label` |
| `#nz-btn-restart` | `처음부터` | 텍스트 |

- **아이콘만 있는 버튼을 만들지 않는다.** `#nz-btn-mute`도 아이콘 + `소리 끔` 텍스트다.
- `title` 속성을 접근 이름으로 쓰지 않는다.
- `aria-pressed`를 쓰는 곳은 `#nz-btn-mute` 하나뿐이다. 선택지 버튼에는 쓰지 않는다
  (토글이 아니라 1회성 확정이므로).

## 9. `prefers-reduced-motion`

### 9.1 DOM 측

```css
@media (prefers-reduced-motion: reduce){
  :root{
    --nz-t-fast: 1ms;
    --nz-t-base: 90ms;
    --nz-t-slow: 120ms;
  }
  #nz-root *, #nz-root *::before, #nz-root *::after{
    animation-duration:1ms!important;
    animation-iteration-count:1!important;
    transition-duration:var(--nz-t-base)!important;
    scroll-behavior:auto!important;
  }
}
```

**범위를 `#nz-root` 이하로 한정한 것이 핵심이다.** 전역 `*`로 걸면
`#nz-root`의 형제인 `#nz-gl`과 `#nz-fb-bust`(§12)의 애니메이션까지 1ms로 죽어,
모션 감소 사용자에게 **승인과 반박이 똑같이 보이게 된다.**
3D와 SVG 대체 노직의 모션은 CSS 미디어 쿼리가 아니라
`#nz-root[data-motion="reduced"]`를 읽는 JS가 제어한다(§9.2, 03 §9).

| 요소 | 기본 | 모션 감소 |
|---|---|---|
| 화면 전환 | `opacity` 220ms + `translateY(8px)` | `opacity` 90ms, **이동 없음** |
| 로비 카드 hover/focus | `translateY(-3px)` 140ms | 이동 없음. 테두리 색만 즉시 |
| 판정 카드 등장 | `opacity` + `scale(.97→1)` 220ms | `opacity` 90ms만 |
| 도장 찍힘 | `scale(1.08→1)` 180ms 1회 | 애니메이션 없이 즉시 표시 |
| 진행도 막대 | `width` 380ms | `width` 120ms |
| 진행도 도트 · 현재 표시 | 펄스 없음(기본에도 없다) | 동일 |
| `scrollIntoView` | `behavior:'smooth'` | `behavior:'auto'` |
| 배경 그레인/노이즈 | **사용하지 않음** | — |

### 9.2 3D 측 (레이아웃 문서가 정하는 범위만)

| 항목 | 기본 | 모션 감소 |
|---|---|---|
| 노직 반응 애니메이션 | 0.6~1.2초 유지 | **유지**. 다만 아래 둘을 끈다 |
| 카메라 이동/줌 | 반응 시 소폭 이동 | 카메라 **완전 고정** |
| 화면 흔들림(shake) | **기본에도 금지** | — |
| 포즈 전환 | 이징 보간 | 250ms 선형 크로스페이드 |
| 조명 깜빡임 | 없음 | — |

`window.matchMedia('(prefers-reduced-motion: reduce)')`의 결과를 `NZ.motion.reduced`에
한 번 넣고, `change` 이벤트로 갱신한다. 렌더 루프 안에서 `matchMedia`를 매 프레임 호출하지 않는다.

### 9.3 번쩍임 금지 (WCAG 2.3.1)

- **어떤 요소도 초당 3회를 넘는 휘도 변화를 만들지 않는다.** 판정 카드·도장·말풍선 전부
  1회성 페이드/스케일이며 반복 애니메이션이 없다.
- 전체 화면 플래시(흰색/색 플래시)를 쓰지 않는다. 오답 반응에서 화면을 붉게 번쩍이는 연출 금지.
- 지휘봉으로 책상을 치는 순간의 시각 강조는 **말풍선이 나타나는 것**과
  **캔버스 열 하단 6px 라인이 `#FF9A62`로 1회 페이드(220ms)** 까지다. 화면 흔들기 없음.
- 요구사항 §5: 지휘봉은 사람을 때리지 않는다. 카메라를 학생 쪽으로 밀어붙이는
  줌인(dolly-in)도 위압적으로 읽히므로 **오답 연출에서 카메라 전진 금지**.

다시 선언해야 한다. 이 프로젝트에서는 **합성 토큰을 만들지 않는 것**으로 회피한다.

### 11.2 클래스 네이밍

**id와 `data-*`는 02가 소유한다. 이 문서는 클래스와 커스텀 프로퍼티만 정한다.**
02가 이미 쓰고 있는 표기(`nz-file-title`, `nz-choice-key`, `nz-fb-word`)는 **하이픈 1단**이다.
BEM `__`을 새로 도입하지 않는다 — 한 파일 안에서 두 표기가 섞이는 것이 더 나쁘다.

| 규칙 | 예 |
|---|---|
| 접두사 | 모든 클래스·id·커스텀 프로퍼티에 **`nz-`**. 예외 없음 |
| 클래스 | `.nz-<블록>-<요소>` 하이픈 1단 — `.nz-file-title` `.nz-choice-key` `.nz-fb-word` `.nz-dot` `.nz-key` |
| **상태** | **`data-*` 속성**. 02가 정한 것을 그대로 쓴다 — `[data-screen]` `[data-phase]` `[data-state]` `[data-current]` `[data-picked]` `[data-expected]` `[data-verdict]` `[data-review]` `[data-three]` `[data-motion]` `[data-sound]` |
| 레이아웃이 추가하는 `data-*` | `#nz-gl[data-split]`, `#nz-fb-line[data-bubble]` **2개뿐** |
| `.is-*` / `.has-*` | **쓰지 않는다.** 상태는 전부 `data-*`다 |
| 유틸 | `.nz-sr` `.nz-nb` `.nz-ko` `.nz-en` `.nz-tnum` `.nz-icon` |
| 중첩 깊이 | 선택자 최대 **3단계**(`#nz-case[data-phase="feedback"] .nz-choice`). 그 이상 금지 |
| `!important` | `.nz-sr`, `[hidden]`, 모션 감소 블록 **3곳에서만** |

- **상태를 인라인 스타일로 표현하지 않는다.** JS는 `el.dataset.*` 와
  `el.style.setProperty(--nz-…, v)`만 한다. `el.style.display`를 쓰지 않고 `el.hidden`을 쓴다.
- 인라인 커스텀 프로퍼티는 **`--nz-fb-accent` 하나만** 허용한다(§1.2).
- `[hidden]{display:none!important}`를 전역에 1줄 선언한다(클래스 규칙이 `@hidden`을 이기지 못하게).
- 전역 태그 선택자는 `*`(box-sizing), `html, body`, `button`, `canvas`, `mark`(§4.5 리셋) 5개로 제한한다.
- CSS는 파일 하나(`src/nz-ui.css`)로 두고, 순서는
  ① 토큰 → ② 리셋 → ③ 레이아웃 골격 → ④ 컴포넌트 → ⑤ 상태(`data-*`) → ⑥ 미디어 쿼리 → ⑦ 모션 감소.
  모션 감소 블록이 **항상 마지막**이어야 `!important` 없이도 이길 수 있는 자리를 갖는다.

### 11.3 JS 쪽 접점 (레이아웃이 요구하는 것만)

02 §7.1의 모듈 분리(`#nz-gl` = court3d.js / `#nz-root` 이하 = ui.js)를 지킨다.

| 전역 | 소유 | 책임 |
|---|---|---|
| `NZ.layout.mode()` | ui.js | `split` \| `stack` 반환. `matchMedia("(min-width:1024px)")` **1개만** 구독 |
| `#nz-gl[data-split]` | ui.js | `data-screen`이 `case`가 될 때 `"1"`, 나갈 때 제거. ui.js가 캔버스에서 만지는 유일한 것 |
| `ResizeObserver(#nz-gl)` | court3d.js | 렌더러 리사이즈 + `camera.aspect` 갱신. `window.resize`를 듣지 않는다 |
| `NZ.motion.reduced` | ui.js | boolean. `matchMedia`의 `change`로 갱신하고 `#nz-root[data-motion]`에 반영 |
| `NZ.a11y.say(text)` | ui.js | `#nz-live` 갱신(동일 문자열이면 U+200B 토글) |
| `NZ.a11y.alert(text)` | ui.js | `#nz-alert` 갱신. **저장 불가 알림 1건 전용** |
| `NZ.a11y.focus(el)` | ui.js | `rAF` 1회 뒤 `.focus({preventScroll:true})` |

**`100vh`를 쓰지 않는다.** `.nz-screen`은 `position:absolute; top:var(--nz-hud-h); bottom:0`이고
`#nz-root`가 `position:fixed; inset:0`이라, 높이 계산에 뷰포트 단위가 전혀 등장하지 않는다.
캔버스 밴드 높이 `--nz-band-h`에만 `vh`가 남는데(`min(28vh, 240px)`),
이 값은 주소창이 움직여도 몇 px 흔들릴 뿐 레이아웃을 깨지 않는다.

## 12. WebGL 실패 시 — 레이아웃은 바뀌지 않는다

02의 `#nz-root[data-three="off"]`가 스위치다. 열 비율·패널·키맵·세로 예산은 전부 동일하다.

**추가 요소는 정확히 1개만 허용한다: `<svg id="nz-fb-bust" aria-hidden="true" hidden>`.**
`#nz-gl`의 형제이고, court3d.js가 소유하며, `#nz-gl`과 **같은 사각형**을 차지한다.
`#nz-root::before` 하나로는 관절 4개(머리·눈썹·지휘봉·도장)를 따로 움직일 수 없어
요구사항 §5의 "대기 / 승인 / 반박이 시각적으로 구분되어야 한다"를 지킬 수 없다 —
그래서 03의 요청을 받아들인다. 조건은 셋이다.

1. `#nz-gl`과 동일한 CSS 사각형 규칙을 쓴다(`position:fixed; top:var(--nz-hud-h); …`,
   `[data-split="1"]`일 때 `right:var(--nz-panel-w)`). 레이아웃 코드를 복제하지 말고
   `#nz-gl, #nz-fb-bust{ … }` 한 선택자로 묶는다.
2. `aria-hidden="true"`. 포커스 가능한 요소를 안에 두지 않는다.
3. `#nz-root` 밖에 있으므로 §9.1의 모션 감소 blanket이 걸리지 않는다.
   모션 감소 처리는 03이 `[data-motion]`으로 직접 한다.

배경 판(법정 실루엣)은 그대로 `#nz-root::before`가 담당한다.

| 항목 | 값 |
|---|---|
| 배경 | `--nz-navy-0` 위에 세로 그라디언트 `#101A2E → #0A1020` |
| 내용 | 법정 실루엣 (인라인 SVG를 `background-image: url("data:image/svg+xml,…")` 로, 8KB 이하) |

| 접근성 | `::before`는 접근성 트리에 없고 `#nz-fb-bust`는 `aria-hidden`. 정보 손실 0 — 모든 정보가 패널과 `#nz-live`에 있다 |

### 13.2 `02-화면흐름-상태기계.md`와의 충돌 5건 — 이 문서의 결론

02가 DOM 골격과 id의 소유자다. 아래 5건은 **접근성·레이아웃 판단이 필요해
이 문서가 결론을 내린 지점**이다. 구현 전에 02에 반영하거나, 반대 결론이면 이 문서를 고쳐야 한다.

**협의 1 — `#nz-btn-lobby`의 위치 (02 내부 모순)**

02 §2 전이표 T8은 `CASE·ask` 에서 `#nz-btn-lobby`로 로비에 갈 수 있다고 적었는데,
§7.2 골격은 그 버튼을 `#nz-feedback > #nz-fb-nav` 안에 두었다.
`#nz-feedback`은 `ask` 위상에서 `hidden`이므로 **T8의 버튼 경로가 실제로는 존재하지 않는다.**

> **결론: `#nz-btn-lobby`를 `#nz-hud` 좌측으로 옮긴다.**
> (a) `ask`·`feedback` 양쪽에서 보인다 → T8이 성립한다.
> (b) 패널 세로 예산에서 44px이 빠진다 → §3.1 여유가 +46 → **+90**이 된다.
> (c) 선택지와 화면 좌표를 공유할 일이 원천적으로 없어진다(02 §4.3의 요구).
> (d) `Esc`와 같은 기능이 항상 같은 자리에 있어 학습 비용이 0이다.
> `#nz-fb-nav`에는 `#nz-btn-next` 하나만 남는다.

**협의 2 — 제목 안 숫자 강조용 `titleHTML` 필드**

§6.3의 숫자 강조는 정규식으로 만들 수 없다(`100억`의 `억`, `10초`의 `초`를 놓친다).
콘텐츠 데이터에 `titleHTML: "춤 <i>10초</i>에 <i>3억</i>"` 필드가 필요하다.

> **결론: 콘텐츠 문서가 `titleHTML`을 두면 채택, 아니면 제목을 단색으로 처리하고 이 항목만 삭제한다.**
> 어느 쪽이든 레이아웃 예산에는 영향이 없다. `title`(평문)은 `aria-label` 생성에 계속 필요하므로
> `titleHTML`을 두더라도 `title`을 없애지 않는다.

**협의 3 — 로비 카드의 접근 이름 중복 낭독**

02 골격은 `.nz-file` 버튼 안에 번호·제목·배지를 모두 두고,
거기에 더해 `aria-describedby="nz-file-state-case01"`로 배지를 다시 참조한다.
ChromeVox는 이름(번호+제목+배지)을 읽고 설명(배지)을 **한 번 더** 읽는다.

> **결론: `aria-describedby`를 제거한다.**
> `.nz-file-no`와 `.nz-file-badge`에 `aria-hidden="true"`를 주고,
> 버튼에 `aria-label="사건 3. 춤 10초에 3억. 미열람."`을 ui.js가 상태와 함께 갱신한다.
> 배지 id(`nz-file-state-case01`)는 남겨도 되지만 참조되지 않는다.

**협의 4 — `#nz-hud-clock`의 `aria-label`**

02는 `<p id="nz-hud-clock" aria-label="경과 시간">`을 달았다.
1초마다 값이 바뀌는 요소에 접근 이름이 붙어 있으면 ChromeVox가 커서를 지날 때마다 읽는다.
경과 시간은 주변 정보이고, 같은 값이 `#nz-result-time-v`에 낭독 가능한 형태로 다시 나온다.

> **결론: `#nz-hud-clock`을 `aria-hidden="true"`로 바꾼다.**
> `aria-live`를 붙이는 것은 더 나쁘다 — 5분 동안 300번 낭독된다.

**협의 5 — `#nz-btn-mute`의 초기 상태 (요구사항 위반 가능성)**

02 골격은 `<button id="nz-btn-mute" aria-pressed="true">소리 켜기</button>`이고
`#nz-root`는 `data-sound="off"`다. 셋이 서로 맞지 않는다:
라벨은 *동작*("소리 켜기")인데 `aria-pressed`는 *상태*를 뜻하고, 그 상태가 `true`인데 실제는 `off`다.
요구사항 §5는 **효과음 기본값 OFF**를 명시한다.

> **결론:**
> - 접근 이름은 `aria-label="효과음"`(토글의 대상), 보이는 텍스트는 상태(`소리 끔` / `소리 켬`).
> - `aria-pressed`는 **소리 상태**를 그대로 따른다 → 초기값 `false`, `data-sound="off"`.
> - 라벨을 동작형("소리 켜기")으로 쓰려면 `aria-pressed`를 **제거**해야 한다.
>   동작형 라벨 + `aria-pressed` 조합은 어떤 값을 넣어도 모순이다.

### 13.3 `03-3D연출-명세.md`가 이 문서에 물은 4건 — 답

**답 1 — 폴백 노직 요소 `#nz-fb-bust` (03 §13-D): 허용한다.** 조건 3개는 §12에 적었다.
"새 요소를 추가하지 않는다"는 §12의 원래 문장은 요구사항 §5의 3상태 구분보다 우선하지 않는다.
다만 **1개까지다.** 두 번째 요소가 필요해지면 그건 폴백이 아니라 두 번째 렌더러다.

**답 2 — §9.1의 전역 `animation-duration:1ms!important` (03 §13 기록 항목): 범위를 좁혔다.**
이제 `#nz-root` 이하에만 걸린다. `#nz-gl`·`#nz-fb-bust`는 영향을 받지 않으므로
03의 "포즈(transition)와 장식(animation) 분리"를 되돌릴 필요가 없다.

**답 3 — 로비의 3D 앵커 (03 §13-C): 만들지 않는다. DOM 그리드가 로비의 유일한 조작면이다.**
근거는 성능이 아니라 접근성이다.
(a) 3D 앵커 위에 투명 버튼을 얹으면 포커스 링(§7.4)이 3D 위에 뜨는데,
    조명이 움직이는 배경 위에서 링의 3:1 대비를 보장할 수 없다.
(b) 방향키 2D 이동(§7.2)은 그리드 좌표가 필요한데, 3D 배치는 좌표가 카메라에 따라 바뀐다.
(c) `data-three="off"`에서 어차피 DOM 그리드가 필요하므로, 앵커를 만들면 **로비를 두 벌 유지**하게 된다.
따라서 `setFiles()` / `highlightFile()` / `nz:anchors`는 **레이아웃이 소비하지 않는다.**
3D의 사건 파일 더미는 소품이고, 로비에서 캔버스는 스크림(`rgba(10,16,32,.72)`) 뒤의 배경이다.

**답 4 — 모션 감소에서 `react()` 길이 (03 §13-B, 02 §9와 충돌): 03이 옳다. 0ms로 가지 않는다.**
§9.2에 이미 "노직 반응 애니메이션은 모션 감소에서도 **유지**"라고 적었다.
모션 감소 사용자가 원하는 것은 *움직임이 없는 것*이지 *반응이 없는 것*이 아니다.
끄는 것은 카메라 이동·전진·흔들림이고, 포즈 전환은 250ms 크로스페이드로 남긴다.
이 결정은 §7.3의 입력 유예 450ms와도 맞아떨어진다 — 0ms면 유예가 반응보다 길어져
"버튼이 먹통"으로 느껴진다.

### 13.4 다른 문서에 넘기는 것 (이 문서가 정하지 않는다)

| 항목 | 소유 문서 |
|---|---|
| 상태 스키마, 전이표, 저장·복구, 입력 잠금 로직 | `02-화면흐름-상태기계.md` |

3D 문서에 넘기는 레이아웃 제약은 3개뿐이다.

1. 캔버스는 `#nz-gl`의 실제 `getBoundingClientRect()`만 쓴다. `window.innerWidth`를 읽지 않는다.
2. 분할 모드의 캔버스는 **세로로 긴 사각형**이다(1366에서 738 × 588, 종횡비 1.26).

3. 말풍선(`#nz-fb-line`)이 캔버스 좌하단 `min(520px, …) × 약 100px`을 덮는다.
   그 영역에 판독이 필요한 3D 요소(지휘봉 끝, 도장)를 두지 않는다.
4. 로비 화면에서 캔버스 위에 `rgba(10,16,32,.72)` 스크림이 깔린다. 그 뒤에서 읽혀야 하는
   3D 요소가 있으면 안 된다 — 로비의 정보는 전부 DOM 카드에 있다.
