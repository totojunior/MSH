# SELLING YOSEMITE — 되팔기 시장

외부지문 2 · **4차시** 도입 훅. 마이클 샌델의 *Selling Yosemite: Fairness and the Sacred*(지문 4)를
읽기 **전에** 돌린다.

> ## https://totojunior.github.io/MSH/SR2/YM/

학생은 용산 IMAX 좌석을 놓고 실제로 싸우고, 이기면 팔지 말지 고민하고, 받은 적 없는 돈으로
경매에 뛰어들고, 마지막에 자기가 만든 시장을 본다. 그러고 나서야 요세미티가 나온다.

**답을 주지 않는다.** 화면 어디에도 "이건 불공정하다" "암표는 나쁘다"는 말이 없다.
일어난 일을 숫자로 보여 주고 질문만 남긴다.

## 1. 바로 쓰는 법

### 준비 (수업 10분 전)

| 어디에 | 무엇을 |
|---|---|
| **교탁 PC** (프로젝터) | `screen.html?room=YM2-○` 전체화면. **화면을 한 번 클릭해 소리를 켠다** |
| **선생님 휴대폰** | `admin.html` — 반 고르고 관리자 토큰 붙여넣기 |
| **학생 크롬북** | 아무것도 안 해도 된다. 프로젝터의 **QR**을 찍으면 된다 |

> ⚠️ **조종석(`admin.html`)을 교탁 PC에서 열지 마세요.** 대부분의 교탁 PC는 프로젝터에
> 미러링되고, 관리자 토큰이 교실 벽에 걸립니다. 토큰을 본 학생은 단계를 넘기고 경매를 끝낼 수 있습니다.

### 진행

조종석에는 **다음에 누를 버튼 하나만** 크게 뜬다. 순서를 외울 필요가 없다.

```
입장 열기 → 명단 잠그기 → 예매 시작 → 사전 투표
  → 가질까 팔까 → 예산 배정 → 경매 시작 → 결과 보기 → 요세미티로
```

**활동 22분.** 조종석 위쪽 시계가 목표 시간을 알려 준다. 25분이 한계다.
자세한 진행은 **`교사용-진행안.html`** (인쇄용 A4 2장)을 보세요.

### 반 코드

`YM2-1` ~ `YM2-11` (반별 하나씩) + `YM2-TEST` (리허설용).
반마다 관리자 토큰이 다르다. **다음 반은 방 코드만 바꾸면 된다. 초기화할 필요 없다.**

## 2. 무슨 일이 일어나는가

| 단계 | 학생이 겪는 것 |
|---|---|
| **예매** | 좌석은 **인원의 40%**뿐이다. 33명이면 13석. 눌러서 잡는다. 대부분은 못 잡는다 |
| **사전 투표** | "좌석을 되파는 것을 허용해야 할까요?" — **돈 이야기가 나오기 전에** 묻는다 |
| **가질까 팔까** | 좌석 주인만 고른다. 팔겠다면 시작가(₩20,000~50,000)와 **이유**를 고른다 |
| **예산 배정** | 전원이 받는다. ₩40,000부터 ₩300,000까지. **번 돈이 아니다** |
| **경매** | 좌석 없는 학생만 입찰. 한 사람은 한 좌석에서만 1등이 될 수 있다 |
| **결과** | 사후 투표 → 변화 → 통계. 좌석별 최종 가격 히트맵 |
| **요세미티** | 900 / $20 / $100–150 → 우리 교실과 나란히 → 3문항 투표 → 지문 |

### 왜 40%인가

이 숫자가 활동 전체의 심장이다.
75%로 주면 **팔려는 사람이 사려는 사람보다 많아져서** 경매가 전부 시작가에 낙찰된다.
"₩20,000이 ₩150,000이 됐다"는 장면이 아예 안 나온다.
40%면 13석에 입찰자 20명 — 매물당 3명 남짓이 붙는다.

*(실측: 참가 20명 · 좌석 8석 → 매물 5개 전부 낙찰, 최고 ₩110,000, 정가의 5.5배,
PRICED OUT 6명.)*

### PRICED OUT

결과 화면의 핵심 숫자. **가진 돈 전부를 써도 가장 싸게 팔린 좌석조차 못 산 학생 수.**

원래는 "저소득 절반 vs 고소득 절반이 각각 몇 명이나 좌석을 얻었나"를 보여 주려 했는데,
9명 남짓으로 내는 통계라 노이즈고 **거꾸로 나올 수도 있다.** 지문을 읽기 직전에
첫 번째 반론이 뒤집히면 수업이 무너진다. 뒤집힐 수 없는 숫자로 바꿨다.

## 3. 이 활동만 예외인 것

저장소 규칙(`/CLAUDE.md`)을 세 군데 깬다. **일부러 깼고, 되돌리면 활동이 죽는다.**
자세한 근거는 `docs/00-아키텍처-예외.md`.

| 규칙 | YM |
|---|---|
| "서버도 DB도 로그인도 없다" | **서버를 쓴다.** 실시간 멀티플레이는 서버 없이 불가능하다 |
| `assemble.js` 단일 파일 빌드 | **안 쓴다.** 그 빌드는 `fetch(` 를 만나면 실패한다 |
| "인터넷이 끊긴 교실에서는 파일 하나를 더블클릭" | **못 한다.** 대신 `?demo=1` 과 종이 대체 활동이 있다 |

**개인정보 규칙은 그대로 지킨다.** 실명·학번·점수를 저장하지 않는다.
별명은 학생이 짓고(12자, 욕설은 서버가 거른다), 투표에는 **시각조차 기록하지 않는다** —
좌석 잡은 시각과 대조하면 누가 뭘 골랐는지 역추적할 수 있기 때문이다.
방은 30일 뒤 만료된다.

## 4. 처음 설치할 때 (이미 되어 있음)

1. Supabase 프로젝트를 **Seoul(ap-northeast-2)** 지역으로 만든다. *실시간 예매 경쟁이라 지연시간이 승패를 가른다.*
2. `Project Settings → Data API`: `Enable Data API` **켜기**, `Automatically expose new tables` **끄기**, `Enable automatic RLS` **켜기**
3. SQL Editor 에 `supabase/00-설치-한번에.sql` 을 붙여넣고 Run
4. `supabase/seed-rooms.sql` 을 **한 번만** Run → 반별 관리자 토큰이 **딱 한 번** 표로 찍힌다. 통째로 복사해 저장소 **바깥**에 보관한다
5. `js/config.js` 의 URL·키 확인 (이미 들어 있음)

> `js/config.js` 는 **반드시 저장소에 함께 올라가야 한다.** GitHub Pages 에는 빌드 단계도
> 환경변수도 없다. 이 파일이 없으면 학생 화면이 새까맣게 뜨는데, 교사 노트북에서는
> 멀쩡히 돌아서 원인을 찾는 데 한나절이 걸린다.
>
> 거기 든 키는 **공개용(anon/publishable)** 이다. 브라우저에 실려 나가도록 설계된 키이고,
> 실제 방어선은 데이터베이스의 RLS 와 RPC 다. `service_role` / `sb_secret_` 키는 절대 넣지 마세요 —
> `supabase-client.js` 가 검사해서 앱을 아예 켜지 않는다.
>
> 올리기 전: `git grep -nE 'service_role|sb_secret_'`

## 5. 고칠 때

**`index.html` / `admin.html` / `screen.html` 은 빌드 산출물이 아니다.** 직접 고쳐도 된다.
다른 차시와 달리 `assemble.js` 가 없다.

| 무엇 | 어디 |
|---|---|
| 학생 화면 문구·흐름 | `js/student.js` |
| 조종석 버튼 순서·안내문 | `js/admin.js` 의 `STEPS` |
| 프로젝터 연출 | `js/screen.js` |
| 요세미티 대본 | `js/screen.js` 의 `yosemiteScript()` |
| 오류 메시지(한국어) | `js/client.js` 의 `MESSAGES` |
| **게임 규칙 전부** | `supabase/` — 화면을 고쳐도 규칙은 안 바뀐다. 서버가 판정한다 |

```bash
node SR2/YM/src/serve.js      # http://127.0.0.1:8768/ 로 확인
```

`python -m http.server` 는 쓰지 마세요 — charset 을 안 붙여서 한글이 깨집니다.

## 6. 안 만든 것과 그 이유

나중에 "이게 왜 없지" 싶을 때 보라고 남긴다.

- **경매 중 가격 내리기 / 안 판 사람에게 되사기 제안** — 좋은 아이디어지만 학생이 15초 안에
  이해해야 할 규칙이 하나 더 는다. v2로 미뤘다.
- **파는 사람도 입찰 가능(업그레이드)** — 한 명이 두 좌석을 갖는 경로가 생기고
  정산 분기가 통째로 늘어난다. 좌석 40%만으로 충분한 열기가 나온다.
- **좌석 등급(명당/구석)** — 자동 클릭 스크립트에 이득이 생기고, 뒤풀이 토론이
  "쟤가 반칙했어"로 샌다.
- **Supabase 익명 로그인** — IP 당 요청 제한이 걸려서, 학교 NAT 뒤의 33명 중
  절반이 첫 2분 안에 잠긴다.
- **CAPTCHA · 접속자 실시간 Presence · 분석 테이블 · CSV 내려받기** — 수업 22분에
  기여하지 않는다.
- **좌석 잡기 소리를 학생 기기에서** — 크롬북 33대가 동시에 울리면 수업이 안 된다.
  소리는 교탁 스피커 하나로만 난다.

## 7. 검증 기록

실제 Supabase 에 봇을 붙여 측정했다.

| 항목 | 결과 |
|---|---|
| 같은 좌석 **24명 동시 클릭** | 승자 정확히 **1명**, 나머지는 즉시 `TAKEN` |
| 정산 **40회 동시 호출** | 실제 처리 **1회**, 재호출 0건 (멱등) |
| 돈 총량 | 지급 ₩3,100,000 → 정산 후 ₩3,100,000, **차이 ₩0** |
| 음수 잔액 / 좌석 중복 소유 | **0건** |
| 명단잠금·예산배정 두 번 누르기 | 각각 **한 번만** 적용 |
| 남의 토큰으로 호출 | **401** 거절 |
| 좌석 강탈 / 두 번째 좌석 | 각각 `TAKEN` / `ALREADY_HAVE_SEAT` 거절 |
| 와이파이 끊겨 재시도 | `already: true` — "남이 먼저 잡았다"고 거짓말하지 않음 |
| 봇 20명 전 과정 | 완주. 매물 5개 전부 낙찰, 최고 정가의 **5.5배** |

측정할 수 없었던 것: **실제 교실 33명의 열기.** 그리고 학교 와이파이가 `wss` 를 통과시키는지 —
**수업 일주일 전에 학생 크롬북 2~3대로 실제 교실에서 확인해야 한다.** 교무실 와이파이로 되는 것은
증거가 되지 않는다.
