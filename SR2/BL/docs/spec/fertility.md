## 2. 카운터 계산식 (명시 요구사항)

```
BIRTH_PER_SEC = 133,490,217 / 31,557,600 = 4.230049…    (1년 = 365.25 × 24 × 3600초)
```

구현 규칙:
- **rAF 금지, `setInterval(…, 100)`.** 4.23/초라 236ms마다 1씩 증가 → 100ms 폴링이면 모든 증가를 잡는다. 구형 교실 PC / 원격데스크톱 부담 최소.
- 값이 바뀔 때만 DOM에 쓴다 (`tickLast` 가드).
- `[태어나기]` 누르는 순간 `clearInterval` — 카드 33장 스태거 애니메이션에 CPU 양보.

- 교사가 수업 전 미리 켜두면 자연스럽게 수백~수천이 쌓여 있다. 이게 의도된 동작.

## 6. 의사코드 (핵심부, 실제 코드)

```js
const BIRTH_PER_SEC = 133490217 / 31557600;          // 4.230049…
let tickT0 = 0, tickId = 0, tickLast = -1;

function tickStart(){
  const el = document.getElementById('tickN'); if(!el) return;
  tickStop();
  tickT0 = Date.now(); tickLast = -1; el.textContent = '0';
  tickId = setInterval(function(){
    const n = Math.floor((Date.now() - tickT0)/1000 * BIRTH_PER_SEC);
    if(n !== tickLast){ tickLast = n; el.textContent = n.toLocaleString('ko-KR'); }
  }, 100);
}
function tickStop(){ if(tickId){ clearInterval(tickId); tickId = 0; } }

function introShow(){                       // 로드 / 반 재선택 / R 리셋
  const i = document.getElementById('intro');
  i.classList.remove('off');
  requestAnimationFrame(function(){ i.classList.add('lit'); });
  tickStart();
  var b = document.getElementById('whyBar'); if(b) b.classList.remove('on');
}
function introHide(){                       // [태어나기] 누른 순간
  const i = document.getElementById('intro');
  i.classList.add('off'); i.classList.remove('lit');
  tickStop();
  var b = document.getElementById('whyBar'); if(b) b.classList.add('on');
}
introShow();
```

- 한국 '세계 최저' 표현 — 마카오 0.586, 홍콩 0.751이 있어 217개 지역 중 낮은 쪽 2위다. 둘은 중국 특별행정구라 '독립국 중 세계 최저'가 정확하다. 화면에는 순위 대신 숫자(0.72)만 넣었고, 교사 멘트에만 '독립국 중 세계 최저'로 표기했다.
- 저출산 담론 이탈 위험 — 한국 0.17% / 94% 0명은 화면의 감정적 정점이지만, 교사가 여기서 저출산 정책·인구 위기 얘기를 시작하면 롤스 도입이 아니라 사회 시간이 된다. BRIEF의 '전부 운이다에서 멈춘다' 방침과 충돌한다. screen_text 마지막 문장('이 뽑기의 확률이 이렇게 생겼다는 얘기')을 준비해 두고 15초 안에 끊을 것. 같은 이유로 세계/인도/한국 3중 병렬 카운터는 기본안에서 뺐다.
- '6명 중 1명' vs '17.6%' — 1/0.17549 = 5.70 이므로 '6명 중 1명'은 약간(16.7%로) 과소 진술이다. 정확히 말하려면 '100명 중 18명' 또는 '33명 중 6명'을 쓸 것. 후자는 화면에서 학생이 직접 세어 검증할 수 있어 가장 좋다(기대값 5.79).
- TFR과 출생아 수는 다른 지표다 — '출생아 = 인구 × 출산율'은 개념적 설명이고 실제 계산은 조출생률(CBR)로 한다. 화면에 '14.5억 × 2.0 = 17.6%' 같은 등호 수식을 절대 쓰지 말 것(계산이 맞지 않아 학생이 잡아낸다). why-block.html은 등호 대신 세로 스택으로 배치해 이 문제를 피했다.
- 레이아웃은 실제 1920×1080에서 눈으로 한 번 확인할 것 — rem 예산 계산상 88.4rem / 가용 101.6rem 으로 13rem 여유지만 Pretendard 실제 자간에서 달라질 수 있다. 넘치면 (1) .en 'Nobody chose this.' (2) .tickSub (3) .rule 2줄→1줄 순으로 삭제. #whyBar의 bottom:12.4rem도 footer(11.6rem) 위 위치를 눈으로 볼 것.
- 카운터는 '이 화면이 켜진 뒤' 기준이라 새로고침·반 재선택마다 0으로 리셋된다. 이게 의도다(교사가 수업 직전 켜면 수백 명이 쌓여 있고, 다음 반에서 다시 0부터). 절대 '올해 누적' 같은 기준으로 바꾸지 말 것 — 큰 숫자는 추상적이라 훅이 죽는다.
- 인도 인구비중 17.874%는 217개국 인구 합(8,117,484,624)을 분모로 한 값이다. UN 세계인구(약 81.6억)를 쓰면 17.8% 근처로 소수점이 미세하게 다르다. 화면 표기 '17.9%'는 어느 기준으로도 안전하다.
- data/tfr.json 은 요청대로 flat 형식(iso3 → 값)으로 저장했고 217개국 전부 2023년 값이다. 연도 메타는 별도로 남기지 않았으니 HTML 인라인 시 '출산율(2023, World Bank)' 출처 표기를 어딘가 한 곳에 넣을 것.
- data/why.json 과 data/_agent_scratch/why-block.html 은 신규 생성 파일이다. birth-lottery.html(1.8MB 빌드 결과물)과 template.html은 건드리지 않았다 — template.html 을 고친 뒤 build.py 로 재빌드해야 반영된다.
